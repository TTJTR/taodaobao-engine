# 评估指标与试点计划

[返回首页](README.md)

这里列出下一轮试点建议，不是已测得的成绩、已获批计划或招聘用结果数字。

## 衡量价值

| 指标 | 口径 | 数据来源 |
|---|---|---|
| 有依据方案采用率 | 被业务审核接受的有证据方案数 / 提交审核方案数 | 审核记录与业务回访 |
| 首份可用方案耗时 | 从提交问题到审核认可首版的时长，统计中位数及 P90 | 运行时间与人工审核时间 |
| 无依据承诺漏出率 | 人工标注有无依据承诺且实际发布的输出 / 被评估输出 | 盲审样本与发布记录 |
| 有效引用率 | 支持对应结论且来源有效的引用 / 抽检引用 | 来源版本与人工标注 |
| 审核负担 | 每份被接受资产所需人工分钟数及退回次数 | 审核操作与计时 |
| 单次可用方案成本 | 同批任务模型、搜索等可归属费用 / 最终可用方案数 | Provider 账单与运行记录 |

缺失 Token 计量不能按零成本处理；现有用量汇总覆盖有限，不等同于完整计费系统。
没有对照数据时不能宣称“效率提升百分比”。

## 小范围试点方法

1. 选择一条业务线，获得资料授权，指定审核负责人，先关闭演示数据。
2. 建立包含普通问题、复杂研究和证据不足问题的固定样本，记录原人工流程。
3. 对相近难度问题比较人工与辅助流程，记录资料成熟度、人员经验和模型版本等影响因素。
4. 采用同一审核标准评估，保留失败、放弃和被拦截的任务。
5. 先看错误承诺和引用质量，再看耗时、采用率与成本。
6. 根据试点基线共同确定扩展门槛；不预先填写无依据的增长目标。

## 埋点提案

建议事件：问题提交、检索完成、方案形成、门禁决策、人工接受/退回、来源失效、研究阶段变化。
建议维度：运行 ID、脱敏工作区标识、模型版本、规则版本、阶段时长、结果类型。
这些是新增产品分析设计，不表示事件已全部接入；避免采集正文、凭据和不必要的个人信息。
