# 精简 PRD：可信快速方案闭环

[返回首页](README.md) · 本文为既有设计的面试阅读摘要，不替代或修改冻结接口。

## 目标与范围

目标：销售在客户沟通中获取有企业依据的建议，并清楚识别未确认承诺。
输入为客户画像、问题、已审核历史经验和已审核原子能力；输出包括建议、来源、风险、待确认项及可信边界。

本轮不承诺自动定价、自动签约、任意文件完全解析、未授权数据访问或无人审核发布。

## 业务要求与验收

| 编号 | 规则 | 验收场景 |
|---|---|---|
| P-01 | 只有已审核、来源有效的资产可参与检索 | 待审核与失效资产不能出现在新方案证据里 |
| P-02 | 经验与能力保持不同类型 | 历史案例不能被标注成企业当前交付能力 |
| P-03 | 画像由人确认 | 新情报不能自动覆盖长期画像 |
| P-04 | 每次运行保存独立快照 | 两次运行引用不同版本时可以分别追溯 |
| P-05 | 生成与发布分开 | 模型建议发布但证据不足时，后端仍拦截或复核 |
| P-06 | 依赖失败可理解 | Key 缺失、超时、权限失效显示具体原因与可行动提示 |
| P-07 | 专家协作有研究上下文 | 无研究上下文不能发起；回复回到原任务 |
| P-08 | 示例数据明确标记 | 虚构资料不能被表述为真实企业能力 |

## 页面信息结构

方案页首先给出是否可用及原因，然后展示建议内容、证据、风险和待确认项；用户能够查看来源，并在需要时进入深度研究。
资料页展示来源、处理状态、审核状态与失效原因；不能用单一“成功”状态掩盖尚未审核。
研究页展示阶段、进度、失败原因和可继续的动作。

以上是产品验收意图；实际 UI 覆盖需以真实浏览器验收为准。

## 状态与契约边界

“可用、待确认、失败”等中文描述用于解释业务，并非新增 HTTP 状态枚举。
工程必须保留原 HTTP 路径、字段语义与枚举，新增能力写入增量契约。
AIEngine 保持 extract_profile、extract_experience、extract_capabilities、extract_search_intent、generate_solution 五个方法；Embedding 是共享适配能力。

## 验收数据

准备已审核经验、已审核能力、未审核资料、来源更新、权限撤销、证据冲突、无依据需求和缺少模型配置八类场景。
测试替身验证规则分支；真实数据库和真实模型验证端到端。两类结果分别报告。

## 交付依赖

产品明确业务规则与异常文案；开发实现状态和后端权限；AI 工程负责结构化输出；业务审核人确认适用范围；测试验证正常及失败路径。
具体个人分工需要对应贡献记录确认。
