# 如何在各自 GitHub 展示

[返回首页](README.md)

## 产品求职

将本目录单独作为产品案例仓库，README 即作品集首页；Pin 到个人主页。
仓库描述可写：“AI / ToB 产品案例：企业知识、可信售前决策、产品取舍与验收设计”。
建议标签：ai-product、product-management、case-study、enterprise-knowledge。
先读案例，再按真实负责范围补充个人贡献及可访问证据。仓库独立存在不会自动证明个人拥有整个工程。

## 开发求职

工程仓库保留版本历史，入口突出可运行方式、架构、契约、可信门禁、任务恢复与测试。
使用上游允许的 Fork 或获得授权的独立仓库，保留来源和第三方声明。
个人主页链接到实际负责的 PR、提交或模块；不要把团队提交改写为自己的作者记录。
工程仓库中的 portfolio/developer.md 提供深入阅读入口。

## 上传边界

本目录是可独立上传的纯文档版本，没有 .env、数据库、上传文件、运行日志或上游 Git 历史。
上传时明确 GitHub 账号、目标仓库和可见性；如果仓库已存在，先检查其内容，避免覆盖。
当前目录完成不代表上传成功，远程地址和实际分支必须在上传后核验。

## 展示顺序

个人主页中的对口实习介绍 → 本项目一句话定位 → 产品案例仓库 → 个人贡献证据 → 如有权限再链接工程实现。
本包可直接在 GitHub 阅读，不依赖 Pages、在线模型服务或数据库。
