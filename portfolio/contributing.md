# 团队成员如何使用作品集

[返回导航](README.md)

## 开发成员

在获得源码公开/复用权限后，优先保留上游 Fork 关系和 Git 作者历史。
使用 developer.md 作为介绍入口，将实际负责模块对应到 PR 或提交，保留 THIRD_PARTY_NOTICES.md。
未发现顶层开源许可时不能自行假定全仓可采用 MIT 重新发布。

## 产品成员

使用 product/ 目录作为独立文档作品集：复制目录内容后 README 即 GitHub 首页。
本次已在相邻的 taodaobao-product-portfolio 目录准备同内容独立副本。
无需复制数据库、后端环境、历史附件或客户资料。

## 每个人分别填写的贡献卡

- 角色与时间：仅写真实确认的信息。
- 负责问题：所负责模块解决了什么业务问题。
- 个人动作：选择了什么方案，推动了什么评审或实现。
- 交付证据：PRD、提交、原型、验收或复盘的授权可访问地址。
- 结果口径：方法交付、团队结果、实际效果或待验证目标。
- 协作边界：由谁实现其他模块，AI 辅助用于哪些环节。

这张贡献卡是内部补齐模板；信息未确认时，对外保持项目级案例叙述。
不能把本项目未经确认地归属于某公司实习，也不能把测试数量改写为商业收益。

## 发布操作

确定账号、仓库、可见性后再发布到准确目标。已有仓库先检查，使用独立分支和 PR 避免覆盖。
产品包不包含上游历史；工程 Fork 应保留来源，禁止重写作者记录。
发布后核验首页、链接、个人贡献和远程提交，再用于投递。
