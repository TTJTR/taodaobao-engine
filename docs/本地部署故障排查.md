# 本地部署故障排查

## Docker Desktop 未运行

`start-local.ps1` 显示 Docker Engine 不可用时，启动 Docker Desktop，确认使用 Linux containers，
等待 Engine Running 后重试。可先运行 `docker info`。

## Docker Desktop 在 dockerInference 阶段崩溃

如果 Docker Desktop 窗口提示 `initializing Inference manager`，日志包含
`Docker\run\dockerInference` 和 `The file cannot be accessed by the system`，说明 Linux Engine
尚未启动，项目镜像和 Compose 也没有开始构建。这是 Docker Desktop 的 Windows 启动问题，
已有相同的[官方 issue](https://github.com/docker/desktop-feedback/issues/625)。

先完整退出 Docker Desktop，在 Settings 的 AI 页面关闭 Docker Model Runner，然后升级到修复该问题的
稳定版本并确认 WSL 已更新。`enableInference` 是 Docker 官方支持的开关，定义见
[Docker Desktop 设置参考](https://docs.docker.com/enterprise/security/hardened-desktop/settings-management/settings-reference/#enable-docker-model-runner)。
处理后必须以 `docker version` 同时显示 Client 和 Server 为恢复标准。

不要把 `Reset to factory defaults` 当作首选操作；它可能清除 Docker Desktop 的本地容器、镜像、卷和设置。
如必须重装或重置，应先确认现有 Docker 数据是否需要备份。本项目不会自动修改或清空 Docker Desktop
数据目录。

如果升级和重启 Windows 后仍报错，并且日志依次出现 `dockerInference`、`sailor-ingest.sock` 或
`docker-secrets-engine/engine.sock`，可在 **Docker Desktop 已完全退出** 后备份运行时通信目录。它们不应
包含项目数据库卷，但操作前仍需确认目标路径准确：

```powershell
docker desktop stop
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
Move-Item -LiteralPath "$env:LOCALAPPDATA\Docker\run" `
  -Destination "$env:LOCALAPPDATA\Docker\run.stale-$stamp"
if (Test-Path -LiteralPath "$env:LOCALAPPDATA\docker-secrets-engine") {
  Move-Item -LiteralPath "$env:LOCALAPPDATA\docker-secrets-engine" `
    -Destination "$env:LOCALAPPDATA\docker-secrets-engine.stale-$stamp"
}
docker desktop start
docker version
```

必须在同一次启动前处理所有已报错的运行时目录，否则一次失败可能重新留下另一个 Socket。恢复标准是
`docker version` 同时显示 Client 和 Server。保留 `.stale-*` 目录到 Docker 稳定运行并确认项目数据无误后，
再由用户决定是否清理；不要处理 `%LOCALAPPDATA%\Docker\wsl` 或任何 Docker Volume 数据目录。

## 镜像或系统依赖下载超时

先确认 Docker Desktop 日志中的 `httpproxy.log` 是否显示正在使用预期代理，再单独重试失败的基础镜像：

```powershell
docker pull node:22-slim
docker pull python:3.11-slim
.\scripts\start-local.ps1
```

偶发的 Docker Hub 鉴权超时或 Debian 软件源 `502 Bad Gateway` 通常可以安全重试并复用构建缓存。若持续
失败，应在 Docker Desktop 的代理设置中核对 HTTP/HTTPS 代理，不要为了绕过网络问题使用来源不明的镜像。

## 端口占用

修改 `.env` 的 `FRONTEND_PORT`、`BACKEND_PORT`，同时同步 `PUBLIC_BASE_URL`、
`APP_PUBLIC_BASE_URL`、`APP_FRONTEND_REDIRECT_URL` 和 `APP_CORS_ORIGINS`，再重启。

## 应用持续 restarting

```powershell
.\scripts\logs-local.ps1 -Service app -Tail 300
docker compose config
```

常见原因是 `.env` 仍有占位密钥、Fernet Key 格式错误、数据库密码为空或迁移失败。

## 页面能打开但无法登录

检查 `AUTH_MODE=local`、`APP_LOCAL_ADMIN_USERNAME` 和 `APP_LOCAL_ADMIN_PASSWORD`。
修改后必须重启。浏览器只保存 HttpOnly 会话 Cookie，不保存密码。

## AI 显示未配置

至少填写 `AI_API_KEY`、`AI_BASE_URL`、`CHAT_MODEL`、`EMBEDDING_MODEL` 和正确的
`EMBEDDING_DIMENSION`。兼容服务必须实现 OpenAI Schema 的 `/chat/completions` 与 `/embeddings`。
配置缺失时系统不会回退固定答案或假向量。

## 任务一直排队

运行 `status-local.ps1` 并查看 Worker 日志。任务状态存于 PostgreSQL，重启 Worker 不会丢失。
若模型不可用，任务应进入失败或等待复核状态，而不是显示伪成功。

## 飞书回调失败

开启 `ENABLE_FEISHU=true`、设置 `AUTH_MODE=both` 或 `feishu`，填写 App ID、Secret、验证信息和
`APP_FEISHU_CALLBACK_URL`，并在飞书开放平台配置完全相同的回调地址。局域网私有地址通常不能被
飞书公网回调访问，此时需要用户自行提供安全的 HTTPS 反向代理。

## 数据是否真的保留

执行 `stop-local.ps1` 再 `start-local.ps1 -NoBuild`，数据应仍存在。`docker compose down` 保留卷；
`docker compose down -v` 删除卷，不能用于日常停止。
