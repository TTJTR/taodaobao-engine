### 0.1 2026-08-15 实现口径确认

- P1 以“工作区 API 路由”交付，不做浏览器本地配置，也不引入新的账户权限体系。
- 首期可选择 `dashscope` 或 `deepseek`，能力槽分为 `ai` 与 `interactive-html`。
- `ai` 槽供可信 AI、资料提取、快速方案、Deep Research 和方案演练共同使用；`interactive-html` 槽只供互动 HTML 生成使用。
- API Key 保存前必须进行真实模型请求和 JSON 响应检查；失败不保存、不自动降级为 Mock。
- API Key 只允许服务端加密存储，查询仅返回末四位掩码。删除工作区配置后恢复服务器默认配置。
- Embedding 与既有向量索引的模型及维度绑定，首期仅支持真实连通性检查；没有全量重建索引能力前不得在页面自由切换。
- 允许内置虚构文档作为资料测试数据，但必须使用 `is_demo=true` 与 `builtin://` 来源隔离。业务 API、检索、AI 生成、飞书同步和建群不得返回模拟成功结果。

## 1. 背景

V1 已经具备快速方案、Deep Research、AI 可信核验和演示稿生成能力，但用户对 AI 在后台如何运行仍缺乏可见性：

- 不知道当前任务执行到哪一阶段。
- 不知道哪个执行单元或 Agent 产生了什么输出。
- 任务失败时，不清楚是检索、生成、核验、可信门禁还是下游服务出错。
- 不清楚当前使用的模型、服务模式和连接状态。
- 运行信息主要存在于后端日志，一线员工无法直接查看。

因此 V2 增加一个轻量的 AI 后台工作台，用于“查看和理解 AI 运行”，不承担业务工作台已经具备的状态流转和交付功能。

## 2. 产品定义

AI 后台工作台是一个面向一线员工、管理者和技术人员的共用可观测界面。

它要回答四个问题：

1. 现在有哪些 AI 任务在运行？
2. 每个任务运行到哪里？
3. 每个阶段或 Agent 实际输出了什么？
4. 当前 AI 与下游服务是否正常连接？

默认原则是：

> 能看、能理解、能追溯，但不在后台随意改变业务状态。

## 3. 范围

### 3.1 V2 必须完成

- AI 任务列表。
- 任务运行阶段与进度。
- 阶段/Agent 输出查看。
- 可信决策、主张数量、trace 和错误信息。
- 当前 AI 模型和服务连接状态。
- 一线员工和管理者共用的默认只读界面。

### 3.2 暂不实现

- 团队运行概览。
- 结果交付。
- 待人工处理队列。
- 在后台修改业务流转状态。
- 在后台开始、取消、审批或完成业务任务。
- 独立权限系统和复杂角色配置。
- 明文展示、传输或存储 API Key。

## 4. 信息架构

V2 后台只保留两个一级功能：

```text
运行与设置
├─ AI 运行
└─ 模型连接
```

### 4.1 AI 运行

用于查看任务、阶段、执行单元输出和错误。

### 4.2 模型连接

用于查看当前模型、provider、AI 服务、演示生成服务和 Worker 连接状态。

## 5. AI 运行功能

### 5.1 任务列表

后台工作台需要统一展示以下任务：

- 快速方案。
- Deep Research。
- 演示稿/HTML 生成。

列表字段：

|字段|说明|
|---|---|
|任务标题|客户或业务可识别名称|
|任务类型|快速方案 / Deep Research / 演示稿|
|发起人|创建任务的用户|
|创建时间|任务进入队列的时间|
|当前阶段|排队、检索、生成、核验、门禁、渲染等|
|运行状态|等待、运行中、完成、待复核、失败、过期或阻断|
|任务 ID|唯一资源 ID|
|Trace ID|用于对应日志和调用链路|

### 5.2 任务详情

点击任务后，右侧展示：

1. 任务基本信息。
2. 当前状态和阶段。
3. 阶段时间线。
4. 每个阶段或 Agent 的输入摘要、输出摘要和执行时间。
5. 可信决策或视觉校验结果。
6. 失败阶段、错误码和可读错误摘要。
7. 关联业务对象，并提供“回到原工作台”链接。

### 5.3 阶段展示

快速方案默认阶段：

```text
排队
→ 上下文与证据检索
→ 候选方案生成
→ Claim 拆解与核验
→ 修订
→ Trust Gate
→ 完成
```

Deep Research 默认阶段：

```text
排队
→ 问题规划
→ 子问题研究
→ 路线比较
→ 证据审计
→ 报告合成
→ 完成
```

演示稿默认阶段：

```text
上游可信门禁
→ 风格画像读取
→ PresentationSpec 规划
→ HTML 渲染
→ 视觉 QA
→ 完成 / 待复核
```

### 5.4 Agent 输出展示规则

- 只有当后端持久化了独立 Agent/执行单元时，才按 Agent 展示。
- 如果当前实际上只是单模型串行执行，页面必须显示“阶段”或“执行单元”，不得伪装为多 Agent。
- 每个执行单元至少显示：名称、状态、开始/结束时间、输出摘要、模型版本和错误。
- 默认只展示可读摘要，不直接展示内部思维过程、完整 Prompt、API Key 或未脱敏上下文。
- 输出超长时先展示摘要，技术人员可根据 trace 查看日志或受控的完整产物。

### 5.5 可信结果展示

快速方案需展示：

- TrustDecision：`RELEASE / DOWNGRADE / REVIEW / BLOCK`。
- 主张总数、已发布数、待复核数。
- 当前候选方案版本。
- verifier、门禁策略和阈值版本。
- 阻断或降级的 reason codes。

演示稿需展示：

- 上游 TrustDecision 和版本。
- `READY / NEEDS_REVIEW / STALE / BLOCKED / FAILED`。
- Chromium 渲染、打印和资源校验是否通过。
- provider 是 Mock 还是 Live。

## 6. 模型连接功能

### 6.1 P0：只读连接状态

页面展示：

|服务|展示信息|
|---|---|
|AI 方案服务|状态、Mock/Live、provider、模型名称、最近检测时间|
|Deep Research|状态、工作流版本、当前执行模式|
|演示生成服务|状态、Mock/Live、provider、视觉 QA 能力|
|Worker 队列|queued、running、failed 和 stale lease 数量|
|飞书集成|状态和 Mock/Live|

如果后端没有返回 provider 或模型名称，页面应显示“后端未暴露”，不能猜测。

### 6.2 P1：个人 API Key 替换

个人 API Key 是后续功能，P0 只展示不修改。实现前必须先具备：

1. 后端加密存储。
2. 前端只能读取掩码、状态和最后更新时间。
3. 提交新 Key 前执行连通性、模型权限和额度测试。
4. 不将 Key 放入 URL、日志、错误文本或浏览器本地存储。
5. 记录更新人、时间、provider 和测试结果，但不记录密钥原文。
6. 当个人 Key 无效时，按已确认的后端策略决定是否回退到 workspace 默认 Key。

## 7. 只读与业务流转边界

### 7.1 后台允许的操作

- 查看、搜索和筛选任务。
- 查看阶段和执行单元输出。
- 查看错误、trace 和可信结果。
- 刷新任务和服务状态。
- 跳转回原业务工作台。
- P1 在安全后端接口完成后替换本人 API Key。

### 7.2 后台不允许的操作

- 改变方案、Deep Research 或演示稿的业务状态。
- 跳过核验、门禁或人工确认。
- 直接将失败任务改成完成。
- 在后台完成业务审批、结果交付或待人工处理。
- 修改其他用户的模型凭证。

业务状态的变更必须回到对应工作台，例如快速方案、Deep Research、专家协作或演示稿页面。

## 9. 后端数据与接口需求

### 9.1 统一任务查询

```http
GET /api/v1/runtime/tasks
GET /api/v1/runtime/tasks/{task_id}
GET /api/v1/runtime/tasks/{task_id}/steps
```

任务列表需要兼容方案、Deep Research 和演示稿，而不是要求前端分别查询多张表后自行拼装。

### 9.2 执行步骤数据

每个步骤至少包含：

```json
{
  "step_id": "step_xxx",
  "task_id": "task_xxx",
  "name": "claim_verification",
  "display_name": "Claim 核验",
  "executor_type": "stage",
  "executor_name": "solution_verifier",
  "status": "completed",
  "started_at": "2026-08-10T10:00:00Z",
  "finished_at": "2026-08-10T10:00:04Z",
  "duration_ms": 4000,
  "input_summary": {},
  "output_summary": {},
  "model": "provider/model",
  "attempt": 1,
  "error_code": null,
  "error_summary": null
}
```

### 9.3 连接状态

```http
GET /api/v1/model-connections
POST /api/v1/model-connections/{provider}/test
```

P1 增加：

```http
PUT /api/v1/model-connections/{provider}/credential
DELETE /api/v1/model-connections/{provider}/credential
```

Key 查询响应只允许包含：

- `configured`
- `masked_value`
- `source`（personal/workspace/default）
- `updated_at`
- `last_test_status`
- `last_test_at`

不得包含可恢复的密钥原文。

## 11. 安全与隐私

- 所有查询必须按 workspace 隔离。
- 页面不展示完整 Prompt、内部思维过程或不必要的原始上下文。
- 客户事实、证据引用和错误摘要必须继承原始资源的权限边界。
- 原证据权限撤销后，后台不得继续显示 quote 或可还原内容。
- API Key 必须加密存储，只能返回掩码。
- 展示输出前要执行脱敏，防止密钥、token、cookie 和个人敏感信息进入页面。
- 默认只读不等于无需身份校验；用户仍需登录并受 workspace 边界约束。

## 12. 分阶段交付

### P0：可查看的 AI 后台

1. 上线“AI 运行”和“模型连接”两个页面。
2. 提供统一任务列表和任务详情 API。
3. 展示阶段、执行单元输出、trace、可信决策和错误。
4. 展示 AI、Deep Research、演示服务、Worker 和飞书状态。
5. 全部功能默认只读，状态处理回到原工作台。

### P1：个人模型连接

1. 查看本人 provider、model 和 API Key 掩码。
2. 安全替换/删除本人 API Key。
3. 连通性、权限和额度测试。
4. 更新审计与 workspace 默认凭证回退策略。

### P2：可观测性增强

1. 任务搜索、组合筛选和导出脱敏运行摘要。
2. 耗时、错误率、重试次数和模型版本的趋势分析。
3. 为管理者增加汇总指标，但不与业务工作台的团队管理重复。

## 14. 完成定义

V2 后台更新完成必须同时满足：

1. 快速方案、Deep Research 和演示稿任务可在同一页查看。
2. 每个任务都有持久化阶段、时间、trace、输出摘要和错误。
3. 页面严格区分真实 Agent 和普通执行阶段。
4. 用户能理解任务为什么成功、降级、待复核或失败。
5. 后台不提供与原业务工作台重复的状态流转、待办处理和结果交付。
6. 模型连接页能真实展示 Mock/Live、provider/model 和 Worker 状态。
7. P0 不保存或修改 API Key；P1 密钥功能通过安全后端接口单独验收。
8. 一线员工和管理者均可访问对自己有权查看的运行数据，且不泄漏跨 workspace 或已撤销权限的信息。
