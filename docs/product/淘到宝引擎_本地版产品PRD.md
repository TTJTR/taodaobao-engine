# 淘到宝引擎本地版产品 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 淘到宝引擎 |
| 产品形态 | Local First 的企业知识驱动型售前智能决策与协作平台 |
| 当前阶段 | 本地产品候选基线，可用于个人体验、作品集展示和受控试点 |
| 目标用户 | 企业销售、售前顾问、解决方案经理、知识审核员和系统管理员 |
| 部署方式 | Windows + Docker Desktop + Docker Compose |
| 能力状态 | 已实现、配置后可用、规划中三种状态，禁止把规划能力描述为已交付 |

本 PRD 是当前公开仓库的产品主入口。企业生产边界见[企业级能力边界与升级路线](../企业级能力边界与升级路线.md)，接口以根目录 `openapi.yaml` 和增量契约为准。

## 2. 产品背景

企业售前工作常见问题包括：资料分散、历史方案难复用、产品能力口径不统一、客户信息反复收集、方案缺少证据，以及大模型容易生成无法兑现的承诺。

淘到宝引擎将客户画像、经过审核的历史经验和企业原子能力沉淀为可追溯资产，再用于快速方案、Deep Research、专家协作、公开情报、招标响应和方案演练。产品的核心价值不是单纯生成文本，而是在生成前控制知识范围、生成时携带来源、生成后执行可信审计。

## 3. 产品目标与非目标

### 3.1 当前目标

1. 普通电脑安装 Docker Desktop 后，可以独立启动完整产品。
2. 本地资料、客户画像、可信资产、任务和方案可以持久化保存。
3. 用户可以自由配置兼容 OpenAI Schema 的 Chat 与 Embedding 服务。
4. 飞书、公开情报等外部能力未配置时不影响本地核心流程。
5. AI 输出必须区分事实、能力、推断和待确认内容，并保留检索快照。
6. 示例资料与真实资料使用同一处理流程，但必须明确隔离和标记。

### 3.2 当前非目标

1. 不把单机 Docker Compose 描述为高可用企业集群。
2. 不提供离线运行的大模型；不配置外部 AI 时，AI 生成功能不可用。
3. 不承诺复杂扫描 PDF、图片 OCR 和所有 Office 格式均可由轻量镜像解析。
4. 不把本地管理员账号视为完整的企业身份与权限体系。
5. 不默认开放公网访问，不承诺现阶段满足等保、审计或行业合规认证。

## 4. 核心业务对象

| 对象 | 定义 |
|---|---|
| Source | 用户主动导入的文件、文本、链接或外部文档来源 |
| Customer Profile | 每个客户唯一、长期维护并需要人工确认的客户画像 |
| Experience | 从历史项目中提取的经验事实，不能与企业能力混用 |
| Capability | 企业当前可以交付的原子能力，需要来源和审核状态 |
| Retrieval Snapshot | 某次运行实际使用的查询、资产版本、来源状态和检索结果快照 |
| Solution Run | 快速方案的一次独立生成记录 |
| Research Task | Deep Research 的长任务、阶段状态、证据和最终报告 |
| Proposal | 外部情报对客户画像提出的候选更新，人工确认后才能生效 |
| Trust Decision | 后端对发布、降级、复核或拦截作出的最终决定 |

## 5. 产品能力范围

| 模块 | 用户价值 | 当前状态 | 关键边界 |
|---|---|---|---|
| 资料库 | 统一导入本地文件、文本和链接并形成可审核来源 | 已实现 | 轻量镜像不包含重型 OCR；飞书导入需单独配置 |
| 客户画像 | 长期复用客户背景、需求、约束与待确认信息 | 已实现 | 新信息先形成候选更新，不自动覆盖长期画像 |
| 可信资产 | 分开管理历史经验和企业原子能力 | 已实现 | 只有已审核且来源有效的资产可检索 |
| 快速方案 | 在会议和临时沟通中快速生成结构化建议 | 配置 AI 后可用 | 无企业依据时必须拒绝编造 |
| Deep Research | 对复杂问题分阶段检索、编排、审计并形成报告 | 配置 AI 后可用 | 长任务由 Worker 执行，保留独立运行记录 |
| 专家协作 | 基于研究上下文向真实贡献者或审核人补充求证 | 配置飞书后可用 | 回复先回到研究任务，不自动成为已审核经验 |
| 情报与招标 | 采集公开信息、解析要求、匹配证据并拦截缺口 | 按 Provider 配置可用 | 外部搜索未配置时明确不可用，不伪造结果 |
| 方案演练 | 模拟客户角色、异议和危险承诺并给出评估 | 配置 AI 后可用 | 评分是辅助判断，不替代人工审核 |
| HTML 交付 | 将研究结果生成为浏览器可打开的互动方案 | 已实现 | 浏览器负责渲染；输出仍受事实审计约束 |
| 模型与服务配置 | 管理 AI、飞书及可选 Provider 状态 | 已实现 | 密钥仅在后端保存，页面和接口只显示脱敏值 |

## 6. 核心用户流程

### 6.1 首次启动

1. 用户启动 Docker Desktop。
2. 用户运行 `scripts/start-local.ps1`。
3. 脚本自动创建 `.env`、生成本地密钥并启动全部容器。
4. 数据库自动执行迁移，页面展示核心服务和可选 Provider 状态。
5. 用户使用自动生成的管理员凭据登录，在配置页填写自己的 AI 服务。

### 6.2 从资料到方案

1. 用户创建或选择客户。
2. 用户导入资料并选择处理用途。
3. 系统提取候选画像、经验或能力。
4. 审核员确认内容、来源和有效性后发布资产。
5. 用户发起快速方案或 Deep Research。
6. 系统分别检索经验与能力，生成本次运行快照。
7. AI 生成结构化结果，后端 Trust Gate 决定发布、降级、复核或拦截。

### 6.3 外部信息回流

1. 公开情报或专家回复进入独立候选区。
2. 系统展示来源、冲突、影响字段和可信边界。
3. 用户人工确认后，信息才进入客户画像或知识审核流程。
4. 未确认内容不能直接成为长期画像或在线可信资产。

## 7. 功能要求

### 7.1 资料与资产

- 支持粘贴文本、链接和本地文件的统一资料入口。
- TXT、文本型 PDF、DOCX 和 XLSX 由默认轻量解析器处理。
- 资料提取结果必须经过人工审核才能进入在线可信资产。
- 来源更新、删除或权限失效后，关联旧资产暂停检索。
- 演示资料必须保存 `is_demo=true`，并与真实业务空间隔离。

### 7.2 客户画像

- 一个客户维护一份长期画像。
- 快速方案、Deep Research、情报和演练复用同一画像。
- 外部信息只能生成 Proposal，用户确认后才合并。
- 合并过程保留修改前内容、候选内容、确认人和时间。

### 7.3 快速方案

- 输入客户、问题和可选补充上下文。
- 返回方案正文、来源引用、风险、待确认项和可信边界。
- 经验与能力必须分开检索和标识。
- AI 不得将推断包装为企业事实或企业能力。

### 7.4 Deep Research

- 支持创建任务、查询阶段进度、失败状态和最终报告。
- 阶段至少覆盖需求分析、经验检索、能力检索、方案编排和事实审计。
- Worker 重启后任务记录不得消失；可恢复策略以任务状态机为准。
- 证据冲突必须保留，不得静默选择对业务更有利的一方。

### 7.5 配置中心

- Chat Model 与 Embedding Model 分开配置。
- 支持切换兼容 OpenAI Schema 的 Base URL、模型和 API Key。
- 密钥不能写入前端代码、Git、日志或接口响应。
- 页面只能展示脱敏后的密钥，并提示修改是否需要重启。
- 飞书、公开情报和其他外部服务分别提供启用开关与配置状态。

## 8. 可信与安全规则

以下规则属于产品底线，不得因界面或模型升级而绕过：

1. 历史经验与企业原子能力分开管理、分开检索。
2. 只有已审核且来源仍有效的资产可以参与在线检索。
3. 原文更新、删除或权限失效后，旧资产暂停检索。
4. 方案内容区分 `historical_fact`、`enterprise_capability`、`ai_inference` 和 `pending_confirmation`。
5. 找不到企业依据时拒绝编造。
6. 每次运行保留独立检索快照。
7. AI 的 `recommended_action` 只是建议，最终动作由后端 Trust Gate 决定。
8. 日志不得输出 API Key、App Secret、Cookie、Token 或文档敏感正文。

## 9. 本地部署要求

Docker Compose 包含前端、后端、PostgreSQL、Redis 和 Worker。PostgreSQL、Redis 与上传文件使用持久化 Volume；容器重启不能导致客户、资料、任务和方案消失。

默认监听 `127.0.0.1`，仅允许本机访问。用户主动设置 `HOST=0.0.0.0` 后才允许局域网访问。前端通过配置访问后端，不允许写死云服务器地址和端口。

启动后必须明确输出：

- 前端地址；
- API 地址；
- API 文档地址；
- 健康检查地址。

## 10. 外部服务降级

| 场景 | 产品行为 |
|---|---|
| 未配置 AI API Key | 资料、画像和已存在数据仍可管理；AI 操作明确提示未配置 |
| Chat 可用、Embedding 不可用 | 不伪造向量检索成功；显示对应 Provider 异常 |
| 飞书未启用 | 本地资料和核心方案流程继续运行；飞书入口显示未配置 |
| 公开情报未启用 | 跳过外部搜索；不得返回预置搜索结果冒充成功 |
| Worker 不可用 | 长任务进入明确失败或等待状态；同步管理页面仍可访问 |
| 增强解析未启用 | 继续支持轻量格式；复杂 OCR 文件提示能力未配置 |

## 11. 验收标准

### 11.1 部署验收

- 全新环境可通过一个 PowerShell 脚本启动。
- 数据库自动迁移，前端可以访问后端。
- 修改前后端端口后仍可启动和访问。
- 本机与局域网监听行为符合 `HOST` 配置。
- PostgreSQL、Redis 和上传文件在容器重启后保留。

### 11.2 安全验收

- `.env`、日志、上传文件和备份不进入 Git。
- API Key 不出现在前端构建物、日志和接口响应中。
- 配置管理接口要求管理员身份。
- 外部服务未配置时返回真实状态，不返回 Mock 成功。

### 11.3 业务验收

- 示例资料通过真实导入、提取和审核流程进入隔离空间。
- 快速方案返回约定的结构化结果和可信分类。
- Deep Research 可以创建任务并查询进度。
- 失效或未审核资产不能进入检索快照。
- 冻结 HTTP 契约和五个 `AIEngine` 方法签名保持不变。

## 12. 产品指标

试点阶段优先观察真实业务价值，不以生成次数替代采用效果：

- 有效资料审核通过率；
- 可追溯引用覆盖率；
- 无依据主张拦截率；
- 快速方案被确认采用的比例；
- Deep Research 完成率和平均恢复次数；
- 画像 Proposal 人工接受率；
- 从提问到可审核方案的耗时。

## 13. 版本路线

### P0：本地产品基线

- 完成一键启动、配置中心、持久化、健康检查和备份恢复。
- 保证核心可信规则、冻结契约和跨平台自动化测试。
- 提供清晰的真实能力、可选能力和规划能力标识。

### P1：受控企业试点

- 接入企业 SSO、RBAC、工作区隔离和完整审计日志。
- 完成密钥托管、数据加密、备份演练、监控告警和容量测试。
- 建立 Provider 超时、限流、重试、熔断和成本治理。

### P2：正式企业服务

- 升级为高可用部署、对象存储、托管数据库和可扩展 Worker。
- 完成安全评审、漏洞治理、灾难恢复、SLA 和合规制度。
- 补齐组织治理、知识生命周期、审批策略和运营分析。

## 14. 契约约束

- 不擅自修改已有 HTTP 路径、字段语义和状态枚举。
- `extract_profile`、`extract_experience`、`extract_capabilities`、`extract_search_intent` 和 `generate_solution` 五个方法签名保持不变。
- Embedding 继续作为共享 Provider 能力，不新增第六个 `AIEngine` 方法。
- 代码与冻结契约冲突时先记录问题，不通过改写契约隐藏冲突。
