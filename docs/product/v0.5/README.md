# 淘到宝引擎MVP方案

## 文件夹目的

本文件夹只讨论当前MVP，不与完整V1产品架构混写。核心目标是：先建设快速检索与深度研究都会复用的能力，再完成第一条可运行的快速线路；同时通过统一契约和每日集成，保证三个人的代码始终可以合并。

## 当前决策

1.可复用的不只是用户画像，还包括客户会话、内容来源、经验资产、原子能力、检索、引用和飞书身份。
2.完整产品抽象为10项一级能力；有数据的MVP只实现前6项。
3.有赛方数据时，优先完成经验沉淀、PRD原子能力拆分和快速检索。
4.没有赛方数据时，优先完成登录、客户会话、用户画像、多轮提问和输出框架，并用Mock经验与能力数据保持接口可联调。
5.Multi-Agent是Deep Research的技术实现，不是一级产品功能，也不进入首个MVP。
6.三人从第一天开始使用同一代码仓库、同一数据契约和同一黄金流程，不等待所有模块完成后再合并。

## MVP黄金路径

```text
登录
→创建客户方案会话
→输入或导入客户背景
→生成并确认共享用户画像
→检索企业经验与原子能力
→输出答案、来源、限制和建议追问
→后续提问继续复用同一画像和资产服务
```
