# 淘到宝引擎邀请码机制与本地生成说明

## 机制

邀请码采用 HMAC-SHA256 签名，格式为 `tdb1.<payload>.<signature>`。Payload 只包含签发时间、过期时间、随机令牌 ID 和固定受众，不包含用户资料或服务器密钥，因此无需可逆加密。

- 无签名密钥无法生成有效邀请码。
- 修改任意字符、过期或超过服务端允许的最长有效期都会被拒绝。
- 服务端只把令牌 ID 的 SHA-256 摘要写入 PostgreSQL，不保存邀请码原文。
- 验证成功后建立十分钟有效的 HttpOnly Cookie；飞书 OAuth 启动时在数据库中原子消费。
- 邀请码可在签名中声明 1 至 100 次总兑换额度；评委共享模式默认 100 次，旧邀请码默认只能兑换 1 次。
- 每次兑换生成独立且只能使用一次的 OAuth 凭证，达到总额度后不能再次验证；容器重启、多 Worker 或多实例均不能绕过额度。
- 轮换签名密钥会立即让尚未使用的旧邀请码失效。

## 首次启用或轮换

在服务器源码目录执行：

```bash
python3 scripts/configure_invitation.py --enable
```

脚本会更新 `/opt/taodaobao/runtime.env`，并将签名密钥写入权限为 `0600` 的 `/root/taodaobao-invitation-signing-secret.txt`。随后重新创建应用容器，使新环境变量生效。签名密钥不要提交到 Git、聊天群或前端代码。

把签名密钥文件通过安全方式复制到管理员自己的电脑，例如保存为 `C:\Secrets\taodaobao-invitation-signing-secret.txt`，并限制该文件只允许管理员读取。

## 在本地生成邀请码

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\generate_invitation.py `
  --secret-file C:\Secrets\taodaobao-invitation-signing-secret.txt `
  --count 1
```

不填写 `--hours` 和 `--max-uses` 时，命令默认输出 1 枚评委共享邀请码：20 天有效，最多成功兑换 100 次。`--hours` 支持 1 至 720 小时（30 天），`--count` 支持 1 至 100。

生成一个 20 天内最多可成功兑换 100 次的评委共享邀请码：

```powershell
.\.venv\Scripts\python.exe scripts\generate_invitation.py `
  --secret-file C:\Secrets\taodaobao-invitation-signing-secret.txt `
  --hours 480 `
  --count 1 `
  --max-uses 100
```

`--max-uses` 支持 1 至 100。有效期表示允许兑换的时间窗口；每次成功验证占用一个名额，即使用户随后未完成飞书登录，该名额也不会自动退回。

也可以直接打开仓库根目录的 `邀请码生成器.ipynb`。Notebook 默认为 `VALID_DAYS = 20`、`MAX_USES = 100`、`COUNT = 1`，直接运行即可生成一枚评委共享邀请码。Notebook 只读取本机签名密钥文件，不会把密钥值写入文件。

生成后只把某一个邀请码发给对应体验人员，不要发送签名密钥。邀请码在验证页验证通过后，再进入飞书 OAuth。

注意：邀请码只对使用同一签名密钥的部署有效。云端生成的邀请码不能拿到未配置同一密钥的本地服务上验证；本地未启用门禁时，页面会直接展示飞书登录入口。

## 运维命令

```bash
# 只检查状态，不显示密钥
python3 scripts/configure_invitation.py --check

# 关闭门禁并从运行环境删除旧配置
python3 scripts/configure_invitation.py --disable
```

部署新版本前必须先执行 Alembic 迁移，以创建 `invitation_redemptions` 表。

## 兼容与迁移

`APP_INVITATION_CODE` 仅用于兼容现有云端单条明文邀请码。配置 `APP_INVITATION_SIGNING_SECRET` 后，服务端只接受新签名邀请码。确认新流程可用后，应清空旧的 `APP_INVITATION_CODE`。

## 评委短邀请码（推荐）

评委入口使用数据库登记的 `tdb-xxxxx` 短码。短码不区分大小写，明文只在创建时显示一次；数据库仅保存由部署签名密钥计算的 HMAC 摘要。默认有效 20 天、最多成功兑换 100 次。

在已完成迁移的应用镜像中执行：

```bash
python -m app.cli.create_short_invitation --days 20 --max-uses 100
```

短码必须先登记到目标部署的数据库，因此不能像旧的长签名令牌一样只在离线 Notebook 中生成。旧 `tdb1.<payload>.<signature>` 令牌继续兼容，但不再建议发送给评委。
