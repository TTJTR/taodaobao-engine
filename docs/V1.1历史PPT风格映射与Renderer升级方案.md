# V1.1 历史 PPT 风格映射与 Renderer 升级方案

## 1. 文档目标

本阶段不推翻 FactLedger、FactBinding、EvidenceGuard、SlidePlan、LayoutEngine 和双 Renderer 架构。
目标是解决当前测试暴露的问题：历史 PPT 已提取出颜色、字体、形状与坐标，但进入 Renderer 后只剩基础色板、字体和
固定 `layout_token`，导致不同参考稿生成的页面只是“换色换字体”，结构和组件皮肤几乎完全一致。

目标链路：

```text
历史 PPTX
  -> SafePPTXParser（只读取视觉白名单）
  -> StyleFeatureSet（脱敏原始视觉统计）
  -> StyleProfileBuilder（聚类、归一化、置信度）
  -> StyleProfile v2（DesignTokens + ComponentSkins + LayoutArchetypes）
  -> TemplateCompiler（编译为受限 LayoutTemplate）

FactLedger -> Molly SlidePlan -> Materializer -> EvidenceGuard 预检
  -> ProfileScoped LayoutEngine -> PositionedSpec -> EvidenceGuard 终检
  -> HTMLRenderer / PPTXRenderer
  -> Playwright / PowerPoint 视觉门禁
```

## 2. 当前问题与根因

三个真实样本的技术验收均通过，但人工查看 PowerPoint PNG 后视觉质量不通过：

- 卡片面积过大，内容集中在中部，留白失衡。
- 标题字号直接按历史基础字号比例放大，部分达到不合理尺寸。
- 正文统一垂直居中，没有卡片标题、正文、来源脚注的层级。
- 边框统一使用辅助色，未学习历史 PPT 的圆角、粗细、填充与装饰规律。
- 三份参考稿虽提取出不同布局模式，最终仍落到同一套固定 `two_column` 坐标。
- `layout_grammar` 是字符串，Renderer 无法可靠消费其中的坐标、频率和置信度。

根因不是“已有 Renderer 不能使用”，而是提取结果与 Renderer 中间缺少结构化编译层。

## 3. 不可破坏的边界

1. StyleProfile 只携带视觉和叙事规则，不携带历史 PPT 的业务文本、数字或客户名称。
2. AI 只能输出 SlidePlan，不输出 HTML、CSS、PPTX、绝对坐标、颜色或字体。
3. TemplateCompiler 与 Renderer 均为确定性代码，不调用 AI、数据库或网络。
4. 历史几何特征只能编译为白名单模板，不能直接成为任意自由坐标代码。
5. TemplateCompiler 不创建、删除、合并或改写事实组件。
6. HTML 与 PPTX 必须消费同一份 PositionedSpec 和同一份 CompiledStyle。
7. 布局前检查 FactBinding，布局后重新检查事实指纹；视觉优化不能修改任何事实文本和数字。

## 4. 开源代码采用策略

### 4.1 可直接移植或改造

#### aiden0z/pptx-renderer

重点复用：

- `RenderContext` 的页面尺寸、坐标与继承上下文思想。
- `TextRenderer` 的文本框内边距、段落、行距、对齐、字号与字体映射。
- `ShapeRenderer` 的填充、边框、圆角和透明度映射。
- Theme、Master、Layout、Placeholder 的继承解析；当前项目已有一部分 Python 移植。

迁移要求：保留 Apache-2.0 notice；只移植视觉计算，不移植历史业务正文读取和展示逻辑。

#### Presenton

重点复用：

- Template、Layout、Element 的分层模型。
- 受限模板注册和 Schema 到 HTML Fragment 的分发模式。
- 模板容量检查和渲染前验证。

迁移要求：将自由内容字段替换为当前项目的 SemanticComponent 和 FactBinding，不采用模型生成页面代码的部分。

#### Presentation AI

继续复用当前已移植的 OOXML relationship、`clrMap`、Theme Palette、Font Scheme 算法，并补充主题字号层级、
shape fill/line 和 layout usage frequency 的结构化产出。

#### PptxGenJS

继续作为 PPTX 写入引擎，复用其文本、Shape、表格和图片的确定性 API。PptxGenJS 只负责写 OOXML，不能承担
模板选择、事实组织和内容改写。

### 4.2 只参考设计、不直接复制

- SeaSlides 的 Strategist -> Executor -> Renderer 分层和 Build Feedback。
- DeepSlides 的 Content -> Slide Design -> Implementation 分层。
- 任何让 LLM 输出自由 HTML/CSS、任意坐标、数字或业务陈述的实现。
- 任何允许上传可执行模板、JavaScript 或任意外部图片 URL 的实现。

## 6. StyleFeatureSet 设计

StyleFeatureSet 是解析器内部的脱敏统计，不直接对外展示：

```text
StyleFeatureSet
  canvas: width, height, aspect_ratio
  color_samples: color, role, frequency, page_coverage
  font_samples: family, size_pt, weight, role, frequency
  shape_samples: kind, normalized_geometry, fill, line, radius_hint
  page_samples:
    normalized_boxes
    title_band
    column_count
    card_grid
    image_region
    density
  master_layouts: placeholder roles and normalized geometry
```

安全规则：

- 不保存 `<a:t>`、图表值、备注、OLE、嵌入对象或链接目标。
- 坐标统一归一化到 0-10000。
- 颜色和字号按频率统计，不保留其原始文本上下文。
- page sample 只保存 `shape_1/shape_2` 等匿名标识。

## 7. StyleProfile v2 设计

### 7.1 DesignTokens

```text
DesignTokens
  colors:
    canvas, surface, primary, secondary, accent, text_primary, text_muted, border
  typography:
    display, title, subtitle, body, evidence, footnote
    每级包含 font_family, size_pt, weight, line_spacing, color_token
  spacing:
    page_margin, section_gap, component_gap, card_padding
  shape:
    radius, border_width, border_style, shadow, surface_fill
  decoration:
    title_rule, accent_bar, page_number, header_footer
```

字号不能无限继承历史值，必须经过安全范围归一化：

- display：32-48 pt
- title：26-38 pt
- subtitle：20-28 pt
- body：16-24 pt
- evidence：14-20 pt
- footnote：10-14 pt

保留历史 PPT 的层级比例，但超出范围时整体缩放，禁止出现当前测试中的超大标题。

### 7.2 ComponentSkins

```text
ComponentSkin
  token
  applies_to
  fill_token
  border_token / border_width
  radius
  padding
  heading_style
  body_style
  alignment
  vertical_alignment
  accent_placement
```

第一批冻结：`plain_text`、`outline_card`、`filled_card`、`accent_bar_card`、`metric_focus`、
`comparison_split`、`timeline_nodes`、`process_steps`、`source_footer`。

正文默认顶部对齐；只有指标和封面允许垂直居中。卡片标题与正文必须分开创建文本框，不能再拼成一个字符串。

### 7.3 LayoutArchetype

```text
LayoutArchetype
  archetype_token
  purpose
  frequency
  confidence
  slots:
    role, normalized_geometry, allowed_components, capacity
  preferred_skin_tokens
  fallback_archetype
```

MVP 白名单：

- `cover_centered`
- `cover_left_aligned`
- `title_body`
- `title_two_column`
- `title_three_cards`
- `metric_with_evidence`
- `comparison_split`
- `timeline_horizontal`
- `process_horizontal`
- `evidence_grid`
- `source_list_compact`

历史 PPT 的几何聚类只能映射到这些白名单 archetype。无法可靠匹配时回退到系统模板，不允许自由执行历史坐标。

## 8. TemplateCompiler

TemplateCompiler 是本阶段最关键的新层：

```text
StyleProfile v2 + system archetype registry
  -> 选择置信度足够的 LayoutArchetype
  -> 将匿名历史 slot 映射为 title/body/card/image/evidence 角色
  -> 应用画布边距和最小间距
  -> 校验容量、重叠、越界和最小字号
  -> 产生只读 CompiledLayoutTemplate
```

编译失败处理：

1. 尝试同 archetype 的安全坐标修正。
2. 切换到该 archetype 的系统 fallback。
3. 仍失败则标记 `STYLE_TEMPLATE_UNUSABLE`，禁止进入 Renderer。

TemplateCompiler 只编译视觉模板，不读取 FactLedger，也不接触组件文字。

## 9. Renderer 升级

### 9.1 共享渲染语义

HTML 和 PPTX 共同消费：

```text
PositionedSpec
CompiledStyle
  design_tokens
  component_skin_by_component_id
  renderer_version
```

两个 Renderer 必须遵循同一映射表：颜色 token、字体角色、内边距、对齐、边框、圆角和装饰元素。

### 9.2 文本渲染

- 标题、正文、来源分别建立文本框。
- 中文优先按字符数、行宽、字号和行距估算；PowerPoint 转图后再检查实际边界。
- 溢出处理顺序：缩小非关键间距 -> 字号在允许范围内回退 -> fallback 模板 -> 分页。
- 禁止通过删字、改写数字或让 AI 重写来解决溢出。
- 字体缺失时按可配置 fallback chain 替换，并写入 RenderDiagnostics。

### 9.3 Shape 与装饰

- 形状填充、边框、圆角、阴影均来自 ComponentSkin 白名单。
- 装饰线和色块不承载事实，不进入 FactBinding，但必须位于组件层下方且不能遮挡正文。
- 不直接复制历史 PPT 图片、Logo 或业务图形；品牌资产后续通过审核资源 ID 单独接入。

## 10. AI、Molly 与 Harness 边界

本阶段不新增 Molly 输出字段。Molly 仍只输出：

- purpose
- layout_token / archetype preference
- component_type
- claim_ids
- priority
- character_budget
- allow_pagination

Harness 继续负责超时、重试、Schema 校验和 Mock/Live 切换。TemplateCompiler、ComponentSkin 选择和 Renderer
全部由后端确定性代码完成，Molly 无权输出颜色、字体、坐标、HTML、CSS 或 PPTX。

## 11. 数据库与 API

MVP 不新增表。继续使用 `VisualStyleProfile.visual_json`，但增加：

```text
schema_version: style-profile-v2
feature_summary
design_tokens
component_skins
layout_archetypes
confidence_report
compiler_version
```

旧 v1 profile 通过适配器补默认 skin 和系统 archetype，保证历史数据可用。确认后的 StyleProfile 仍不可原地覆盖，
修改时创建新版本并保留旧 Presentation 的快照。

API 保持现有路由；`GET /style-profiles/{id}` 后续可增量返回 `schema_version`、`confidence_report` 和预览图。

## 12. 分阶段实施

### R1：Golden 基线与验收门禁

- 固定 test1/test2/test3 仅作为本地参考，不提交含业务数据的原 PPT。
- 提交脱敏 StyleFeatureSet fixture、目标 StyleProfile 和安全示例 PositionedSpec。
- 扩展现有脚本，输出 HTML/PPTX、PowerPoint PNG 和结构化 diagnostics。
- 建立人工评分表：风格相似、层级、留白、可读性、客户可展示性。

验收：基线可重复，所有失败都有截图和机器可读原因。

### R2：StyleProfile v2 与 TemplateCompiler

- 将字符串 grammar 替换为强类型 FeatureSet 与 LayoutArchetype。
- 实现坐标归一化、布局聚类、置信度和 fallback。
- 编译 ProfileScoped LayoutRegistry。

验收：三个样本至少产生两种不同 archetype；同一输入重复编译结果完全一致。

### R3：ComponentSkin 与文本排版

- 移植开源 TextRenderer/ShapeRenderer 中可复用算法。
- 标题、正文、来源拆框；补字体回退、字号范围、行距、padding、边框和对齐。
- HTML 与 PPTX 使用同一 token 映射测试。

验收：当前三张测试图中的超大标题、垂直居中正文和空卡片问题全部消失。

### R4：业务模板覆盖

- 覆盖 cover、two-column、three-card、metric、comparison、timeline、process、evidence、sources。
- 增加确定性分页和模板 fallback。

验收：10 类页面均无重叠、越界、截断和事实变化。

### R5：视觉闭环与人工评审

- HTML 使用 Playwright 三视口截图。
- PPTX 使用 PowerPoint；CI/服务器优先补 LibreOffice headless。
- 自动检查页数、非空白、边界、重叠、最小字号、对比度和事实原文。
- 保存人工评分和失败原因，反馈只能调整 style/layout，不得修改 FactLedger。

验收：Golden 集中“可直接向客户展示”比例至少 70%，事实安全指标保持 100%。

## 13. 测试矩阵

### 单元测试

- XML 脱敏：敏感文本、数字、备注、图表值和 OLE 不进入 FeatureSet。
- Token 归一化：极端字号、颜色和间距被限制在安全范围。
- Archetype 聚类：同类布局稳定聚合，不同布局不会错误合并。
- TemplateCompiler：未知 archetype、重叠、越界和容量超限 fail closed。
- ComponentSkin：只允许白名单属性，不接受 CSS、JS 或任意路径。
- TextFit：中英文、长数字、长单词和多来源脚注均不溢出。

### 集成测试

- `PPTX -> StyleProfile v2 -> CompiledTemplate -> HTML/PPTX` 全链路。
- HTML/PPTX 页数、组件数量、事实原文、Claim/Source 追踪一致。
- 同一输入重复生成的 Schema、坐标和 OOXML 事实内容一致。
- v1 StyleProfile 兼容适配。

### 视觉测试

- 1440x900、1366x768、390x844 HTML 预览。
- 1600x900 PowerPoint PNG。
- 页面非空、无滚动、无重叠、无越界、无截断。
- 正文不小于 16 pt，来源不小于 10 pt；标题不超过 48 pt。
- 人工检查风格相似度、信息层级、留白与企业感。

### 事实安全回归

- 未知 Claim/Evidence/Source 拦截率 100%。
- 数字和 verbatim 文本篡改拦截率 100%。
- Style 编译与 Renderer 前后事实指纹一致率 100%。
- 历史 PPT 业务文本进入 StyleProfile 的数量为 0。

## 14. MVP 暂不实现

- 任意历史 PPT 像素级复刻。
- 直接复制历史图片、Logo、图表、SmartArt 和业务正文。
- AI 生成或修改 CSS、HTML、坐标和数字。
- 自由拖拽编辑器和用户上传可执行模板。
- 动画、视频、3D 和复杂交互。
- 任意外部字体下载和图片 URL。
- 无审核品牌资产自动进入生成稿。

## 16. 推荐下一步

下一次编码只做 R1 和 R2，不同时大改 Renderer：

1. 冻结 StyleFeatureSet、DesignTokens、ComponentSkin、LayoutArchetype Schema。
2. 把现有字符串 `layout_grammar` 升级为强类型内部结构。
3. 用 test1/test2/test3 生成可审查的 v2 profile 和 archetype 聚类报告。
4. 实现 TemplateCompiler，并证明三个样本能编译出不同、安全、可回退的 LayoutTemplate。
5. R2 验收后再进入 TextRenderer/ShapeRenderer 移植，避免提取层和渲染层同时变化导致无法定位问题。
