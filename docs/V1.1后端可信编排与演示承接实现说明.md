# 淘到宝引擎 V1.1 后端可信编排与演示承接实现说明

## 1. 范围与冻结边界

本实现承接 `后续升级需求/03_后端可信编排与演示生成承接PRD.md`，并为
`02_历史PPT风格驱动HTML生成PRD.md` 提供后端控制面。根目录 `openapi.yaml` 和
`app/contracts/ai.py` 的 V0.5 路径、字段语义及五个 AI 方法签名保持不变；新增接口只记录在
`docs/openapi-v1-incremental.yaml`。

后端仍只调用：

- `extract_profile`
- `extract_experience`
- `extract_capabilities`
- `extract_search_intent`
- `generate_solution`

快速方案通过 `context.schema_version=solution-v2` 请求 Claim Ledger 与核验信号，没有新增第六个
AI 方法。

## 2. 正式快速方案链路

```text
POST turn
→ 同一事务写 Message、SolutionRun、WorkflowTask
→ 独立 Worker 领取 lease
→ 冻结 RetrievalSnapshotV2（来源版本、权限状态、证据位置）
→ generate_solution 执行 generate→verify→revise
→ 后端校验 solution-v2
→ 持久化 Claim/Evidence/Link/QualityAttempt
→ 后端 Trust Gate
→ 写入最终 TrustDecision
→ 只把 RELEASE/DOWNGRADE 的安全结果写入兼容 result 字段
```

`SolutionRun.status` 只描述运行是否完成，`TrustDecision.action` 单独描述是否可发布。AI 返回的
`recommended_action` 仅进入审计记录，不能直接写 `RELEASE`。

## 3. Trust Gate

当前策略版本为 `trust-gate-v1`，阈值版本为 `trust-threshold-v1`：

|规则|检查|结果|
|---|---|---|
|TG01|solution-v2 与 Claim Ledger 完整|结构错误，运行失败且不发布|
|TG02|Evidence 属于冻结快照|BLOCK|
|TG03|证据位置可复现|REVIEW|
|TG04|当前来源版本仍等于审核版本|REVIEW|
|TG05|工作区权限、来源状态和 freshness 仍有效|BLOCK|
|TG06|高风险主张为 ENTAILED|删除后 DOWNGRADE，否则 REVIEW|
|TG07|不存在未解决 CONTRADICTED/快照冲突|REVIEW 或 BLOCK|
|TG08|超时与人工覆盖审计完整|REVIEW；缺审计覆盖为 BLOCK|

人工审核使用 expected decision version 乐观锁。审核记录包含审核人、时间、理由、修改前状态、
删除/降级的 claim、证据变更和最终决策，不能只改一个状态值。

## 4. 可恢复任务

`workflow_tasks` 是数据库持久化队列，保存 kind、target、stage、trace、deadline、attempt、lease、
heartbeat 和错误。`python -m app.cli.worker` 使用 `FOR UPDATE SKIP LOCKED` 领取任务：

- 外部调用前先提交任务阶段；
- lease 过期后其他 Worker 可以接管；
- 快速方案共享 60 秒总 deadline 和最多 3 次任务预算；
- 同一 run 只写一条 assistant message；
- retry 创建新的 candidate version，不重复用户消息；
- Docker Compose 中 Worker 等待 App 健康，确保迁移先完成。

## 5. 演示稿后端控制面

后端已实现以下资源和接口：ReferenceDeck、StyleProfile、PresentationRun、
PresentationInputSnapshot、HtmlArtifact、ExportArtifact，以及 PRD 指定的 10 条增量路由。

核心门禁：

- 只有 RELEASE/DOWNGRADE 的方案能生成正式演示稿；
- PresentationInputSnapshot 只包含 released claims 和当前有权限的证据；
- 风格冲突必须人工处理，draft profile 不可跨任务使用；
- 事实区块修改后若不再等于 released claim，会进入 `needs_claim_review`；
- 上游转 REVIEW 时演示稿 stale，转 BLOCK 时演示稿 blocked；
- export 始终复用最新 ready HtmlArtifact，导出失败不会重新调用 AI 或重新渲染。

## 6. HTML Provider 模式

后端提供同一 `PresentationProvider` Protocol 的 Mock 与 Live 两种实现：

- `APP_PRESENTATION_MODE=mock`：只接受 `demo://` 合成参考稿，不读取真实 PPTX；生成结果明确带
  `provider_mode=mock`，视觉报告为未通过，不能伪装成可正式导出稿。
- `APP_PRESENTATION_MODE=live`：必须配置 `APP_PRESENTATION_SERVICE_URL`，通过只读版本化 Schema
  调用真实 PPTX/HTML 服务。

Mock 仅用于后端状态机、Schema、幂等和安全测试。真实 PPTX 解析、Chromium/打印 QA 与 PDF 生成
属于独立 HTML 服务；未接入 Live Provider 时健康接口会明确显示 mock。

## 7. 错误与可观测性

新增阶段化错误码：`AI_OUTPUT_INVALID`、`CLAIM_EXTRACTION_FAILED`、
`EVIDENCE_LOCATION_INVALID`、`EVIDENCE_PERMISSION_REVOKED`、`EVIDENCE_VERSION_STALE`、
`VERIFIER_UNAVAILABLE`、`TRUST_REVIEW_REQUIRED`、`TRUST_GATE_BLOCKED`、
`PRESENTATION_UPSTREAM_NOT_RELEASED`、`PRESENTATION_RENDER_FAILED`、
`REFERENCE_DECK_UNSAFE`。

运行、Claim、Evidence、核验器、门禁版本、人工审核和演示版本均进入业务数据库。`GET /health`
额外返回 presentation mode、任务状态计数和 stale lease 数量；普通日志不保存完整 Prompt、Token、
Cookie 或客户来源全文。

## 8. 验证命令

```powershell
alembic upgrade head
python -m app.cli.worker --once
pytest -q
ruff check app tests
```

数据库集成测试需要设置 `TEST_DATABASE_URL`。`tests/test_trust_workflow_e2e.py` 覆盖 20 并发 trace
隔离、Worker lease 接管、人工 BLOCK 联动、演示生成和导出失败复用 HTML。
