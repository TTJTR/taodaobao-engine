# 淘到宝引擎 V2 后端实现与联调说明

## 1. 本次实现范围

本分支以 `8.11_backbone` 为基线，只增加 V2 能力，不改变 V0.5/V1 已冻结契约。

### AI 后台工作台

- 统一任务列表、详情和阶段接口，覆盖快速方案、Deep Research、展示稿、公开情报和方案演练。
- 每条阶段记录明确 `executor` 和 `is_agent`，避免把普通工作流步骤误称为 Agent。
- 模型与服务连接状态、连通性测试；密钥不返回浏览器。
- 新增工作区级 API 路由：可信 AI 与互动 HTML 可在阿里云百炼、DeepSeek 之间选择。保存前执行真实调用，密钥加密落库，仅返回掩码；删除配置后恢复服务器默认路由。
- Embedding 暂为服务器固定路由，避免模型维度变化破坏已有 pgvector 索引；页面只提供真实连通性检查。
- 后台页面保持只读，审批、重试、取消继续由相应业务工作台负责。

### 公开情报与客户画像

- P0 `manual` Search Provider：员工提交公开 URL 与已取得的正文，系统完成来源校验、摘要、事实条目、去重和不可变快照。
- URL 拒绝 localhost、私网、链路本地和云元数据地址。
- 外部情报统一标为 `external_public_information`，不能作为企业经验或能力证据。
- 情报只能先形成画像修改提案；员工确认后写入 `external_intelligence` 命名空间，画像状态重新变为待确认。

### 招标需求与响应矩阵

- 正式业务前端支持粘贴文本，以及 PDF、DOCX、XLSX、UTF-8 TXT 二进制上传；文件上限 50 MiB。
- 二进制文件写入 API 与 Worker 共用的受信任目录，创建带 SHA-256、MIME、安全报告和文件名的 `RawArtifact`，再进入持久化 `tender_parse` Runtime Task。
- PDF/Word/Excel 由 Docling 读取正文和表格；扫描 PDF 使用其 OCR 能力。解析失败、超时、文件头不符或格式未配置时保留错误，不生成要求项。
- 前端展示上传、文件校验、正文/表格解析、要求拆解和证据匹配进度；可通过 Runtime Task 查看 Trace 和失败原因。
- 将招标材料拆分为逐项需求，并识别“必须/不得/须”等强制要求。
- 响应矩阵只接受当前工作区内“已校验 + Embedding 就绪 + 来源有效 + 审核版本等于原文版本”的经验和能力。
- 外部情报只提供客户/行业上下文，不能证明企业能力。
- 找不到内部依据时返回 `missing_evidence` 和明确的“不作能力承诺”，且不能被审核为可承诺。

### 客户异议与方案演练

- 从同一客户画像及快速方案或 Deep Research 建立不可变 `RehearsalContext`。
- 可附加情报快照和招标响应矩阵，但不自动回写画像或资产库。
- 支持角色、难度、关注点、3–10 轮问答、逐轮评分、过度承诺检查、证据边界检查和总结报告。
- 演练是单工作流，不使用 Multi-Agent；专家协作仍只属于 Deep Research 下游。

## 2. 数据流

```text
公开 URL + 正文
  → SearchRun
  → IntelligenceItem（来源/指纹/时效/公开事实）
  → IntelligenceSnapshot（不可变）
  ├→ ProfileIntelligenceProposal → 人工确认 → 客户画像.external_intelligence
  └→ 招标矩阵/方案/演练的外部上下文（不能证明企业能力）

招标材料
  → RawArtifact（原文件哈希 + 受信任存储）
  → TenderDocument + tender_parse Runtime Task
  → DocumentIR（正文/表格 + 页码/段落/单元格）
  → TenderRequirement[]
  → 已校验经验 + 已校验能力（分开校验）
  → ResponseMatrix / ResponseMatrixItem[]
  → 人工逐项审核

客户画像 + 快速方案或 Deep Research
  + 可选情报快照/响应矩阵
  → RehearsalContext（不可变）
  → RehearsalTurn[]
  → RehearsalReport
```

## 4. 本地联调

```powershell
uv sync --all-extras
docker compose -f compose.dev.yaml up -d
$env:APP_DATABASE_URL='postgresql+asyncpg://postgres:postgres@127.0.0.1:55433/taodaobao_v1'
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8000
```

所有 POST/PATCH 继续要求 `Idempotency-Key`，所有业务查询继续按登录用户的 `workspace_id` 隔离。

文件上传还要求 `X-File-Name` 和准确的 `Content-Type`。API 与 Worker 必须把
`APP_TENDER_STORAGE_ROOT` 指向同一个持久化卷；Docker Compose 默认使用
`tender_artifacts:/app/tender-artifacts`。

## 5. 当前边界

- P0 公开情报 Provider 是明确标记的 `manual` 模式，不伪装成通用互联网搜索。接入搜索供应商时实现相同 Provider Schema，不改变业务接口。
- 招标拆解和演练评分当前为确定性规则引擎，确保测试可重复且不会绕过 Trust Gate。后续可通过共享模型适配层增强，不能新增第六个 `AIEngine` 方法。
- V2 业务服务 API 已完成；完整的情报、招标和演练业务页面应由前端分支基于本增量契约开发。
- AI 后台已有页面已接入真实 `/runtime/tasks` 与 `/model-connections`，不再用会话数据自行拼装后台状态。
