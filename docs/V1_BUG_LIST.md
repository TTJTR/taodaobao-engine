## 未关闭缺陷

### BUG-V1-001：飞书资料同步后无法流转到经验库或能力库

| 字段 | 内容 |
|---|---|
| 状态 | 待定位 |
| 严重程度 | S1（阻断资料沉淀主流程和 V1 飞书验收） |
| 发现日期 | 2026-08-09 |
| 发现环境 | 阿里云 `http://8.218.59.190/` |
| 代码基线 | `70d8785`，分支 `feat/v1-integration-acceptance` |
| 运行模式 | 飞书 Live；AI Mock |
| 发现方式 | 用户真实飞书联调验收 |
| 负责人 | 待分配 |

现象：飞书文档可以同步并出现在“资料库”，但后续无法流转到“过去的经验库”或“PRD 原子能力库”，也没有可完成同等结果的直接导入入口。

复现步骤：

1. 使用邀请码和飞书 OAuth 登录云端系统。
2. 点击“同步资料”，选择当前账号有权限的飞书文档。
3. 将资料用途选择为“经验提取”或“能力拆分”，执行同步与处理。
4. 在资料库确认来源已经出现或同步成功。
5. 查看经验库或能力库，无法获得对应的待校验资产，且资料详情中没有可继续完成流转的操作。

期望结果：

- `experience` 用途的资料处理后生成待校验经验，只进入经验库审核流程。
- `capability` 用途的资料处理后生成待校验原子能力，只进入能力库审核流程。
- 处理状态、失败原因和重试入口对用户可见。
- 在人工审核通过前，资产不得参与在线召回。

实际结果：资料同步入口可用，但资料库到经验库/能力库的业务流转不可完成。

影响范围：

- 阻断飞书资料沉淀为企业经验和原子能力。
- 阻断快速方案与 Deep Research 使用真实、已校验企业资产。
- 当前只能证明飞书登录、资料枚举和来源同步可用，不能据此判定资料沉淀闭环通过。

定位检查项：

- Source 创建时的 `purpose` 是否正确保存为 `experience` 或 `capability`。
- Source Job 是否创建并进入 `fetching → parsing → extracting → pending_review/completed`。
- `JobRunner` 是否实际调用 `extract_experience` 或 `extract_capabilities`。
- AI Mock 返回值能否通过 Harness Schema 与 payload adapter 校验。
- Repository 是否落库 Experience/Capability 草稿，并保持正确 `workspace_id`、来源版本和审核状态。
- 前端是否在处理完成后刷新资料、经验和能力三个列表，并显示失败与重试入口。

验收用例：同一份测试文档分别以“经验提取”和“能力拆分”导入；确认两个独立资产库各出现正确的待校验草稿，审核通过后才可被对应检索召回，同时检索快照保留来源引用。
