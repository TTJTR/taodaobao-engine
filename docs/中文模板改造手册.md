# 中文模板改造手册

## 1. 用途与状态

- 版本：V0.1，R1 容量标定基线
- 日期：2026-08-11
- 适用画布：16:9，逻辑尺寸 1600×900
- 适用页面：Cover、Section、Key Message、Evidence、Process、Closing
- 当前状态：`proposed`。本文先冻结测试方法、槽位定义和首版阈值；只有经过真实字体、浏览器和 PPTX 双渲染测试后，容量才能改为 `measured`。
- 目标：先把中文容量摸清楚，再导入和改造更多模板。模板数量不是 R1 指标。

## 2. 基本原则

1. 容量是“字体 + 字号 + 字重 + 槽位宽高 + 行高”的结果，不是一个孤立字数。
2. Pydantic 字段 `max_length` 是接口防滥用边界，不等于演示页面容量。
3. 模板容量必须用真实中文字体验证，不能用英文 lorem ipsum 推算。
4. Renderer 不得为了塞下内容而删字、改数字、压缩横向比例或无限缩小字号。
5. 内容超限的处理顺序固定：换行 → 同类紧凑变体 → 分页 → 有限字号降级 → 失败并要求重规划。
6. 任何经过 FactBinding 的原文不得被自动摘要。`verbatim` 超限时只能分页或换版式。
7. HTML 与 PPTX 必须共享同一容量档位和断行结果，不能各自重新排版。

## 3. 容量的三层定义

每个槽位必须声明三个容量，而不是只写 `max_characters`：

| 容量 | 含义 | 处理 |
|---|---|---|
| recommended | 保持最佳视觉层级和留白的日常容量 | 正常选择该变体 |
| soft_limit | 允许有限换行或切换紧凑变体后的容量 | 记录降级原因 |
| hard_limit | 最小字号下的物理上限 | 超出即分页或失败 |

每个容量记录至少包含：

```yaml
capacity_status: proposed | measured
font_family: Source Han Sans SC
font_file_sha256: pending
font_size_px: 64
min_font_size_px: 52
font_weight: 600
line_height: 1.12
slot_width_px: 1180
slot_height_px: 170
recommended:
  max_lines: 2
  cjk_units: 22
soft_limit:
  max_lines: 2
  cjk_units: 28
hard_limit:
  max_lines: 3
  cjk_units: 36
```

## 4. 中文容量计量方法

### 4.1 CJK Unit 只用于预筛

在进入真实字形测量前，可以用 `cjk_units` 快速判断候选模板：

- 中文、日文、韩文全角字符：1.0
- 全角标点：0.8
- 大写拉丁字母：0.65
- 小写拉丁字母：0.55
- 阿拉伯数字：0.55
- 半角标点：0.35
- 空格：0.3

该值不能决定最终断行。最终结果以 FontTools/OpenType glyph advance 和实际浏览器 `getBoundingClientRect()` 为准。

### 4.2 必测文本类型

每个槽位至少覆盖以下边界语料：

1. 纯中文短句；
2. 中文加全角标点；
3. 中英混排，例如“AI for Process 企业流程”；
4. 中文加数字和单位，例如“提升 12.5%”；
5. 包含不可拆分数字、日期、产品型号；
6. 最长合法标题；
7. 刚好超过 soft limit 的文本；
8. 刚好超过 hard limit 的文本；
9. 极端窄字与宽字组合；
10. 来源标题、版本号和更新时间的组合。

测试语料不得使用真实客户事实。财务数字只使用明确标记的测试值。

### 4.3 标定步骤

1. 固定字体文件和 SHA-256，不依赖系统同名字体。
2. 固定 1600×900 逻辑画布和模板槽位几何。
3. 从推荐字号开始，以 1 个 CJK Unit 为步长增加文本。
4. 分别记录首次换行、推荐行数用满、进入安全区、产生溢出的边界。
5. 仅在模板允许的字号级别间切换，不连续缩放。
6. 在 Chromium/Edge 中测量 DOM 和可见边界。
7. 将同一断行结果输出到 PPTX，在 PowerPoint 和 LibreOffice 中截图复核。
8. HTML 与 PPTX 均通过后，将状态由 `proposed` 改为 `measured`。

## 5. 全局中文排版基线

### 5.1 字体

- 商务无衬线基线：思源黑体或同等 OFL 中文字体。
- 正式叙事基线：思源宋体，仅用于杂志风标题和引述。
- Anton、Montserrat 等拉丁字体只承担数字或英文强调。
- 字体文件未进入受信素材库并冻结哈希前，不得形成 `measured` 容量。

### 5.2 字号下限

| 文本角色 | 推荐字号 | 最小字号 |
|---|---:|---:|
| 封面主标题 | 72-104 px | 60 px |
| 章节标题 | 64-88 px | 56 px |
| 正文页标题 | 38-48 px | 36 px |
| 核心结论 | 32-44 px | 28 px |
| 正文/证据原文 | 22-28 px | 20 px |
| 流程步骤说明 | 20-24 px | 18 px |
| 来源/元数据 | 16-18 px | 14 px |

投屏正文低于 18 px、来源低于 14 px 一律失败。中文大标题必须同时受画布宽度和高度约束，不能只按 `vw` 缩放。

### 5.3 安全区

- 左右外边距：至少 72 px；
- 顶部标题安全区：至少 58 px；
- 底部产物信息或页码安全区：至少 52 px；
- 任意可见内容不得进入画布底部 6%；
- 标题到正文首块的视觉间距：正文页至少 54 px，章节页至少 76 px；
- 相邻卡片正文基线与内边距必须一致。

## 6. 六类页面容量矩阵

以下数值是 R1 的 `proposed` 起始阈值，需要通过第 4 节流程实测。

### 6.1 Cover

**目的**：只负责识别方案和客户，不承担方案摘要。

| 槽位 | recommended | soft limit | hard limit |
|---|---|---|---|
| eyebrow/行业标签 | 4-10 CJK Unit，1 行 | 14，1 行 | 18，1 行 |
| 主标题 | 8-18，最多 2 行 | 24，最多 2 行 | 32，最多 3 行 |
| 副标题 | 12-28，最多 2 行 | 40，最多 2 行 | 54，最多 3 行 |
| 客户/日期/版本 | 每项 4-18，单行 | 每项 24 | 每项 32 |

规则：主标题不得包含一整段价值主张；超过 hard limit 时必须拆分为主标题和副标题。封面最多一个 Logo 区域，不用卡片承载标题。

### 6.2 Section

**目的**：形成叙事停顿和章节切换。

| 槽位 | recommended | soft limit | hard limit |
|---|---|---|---|
| 章节编号 | 1-6 Unit，1 行 | 8 | 12 |
| 章节标题 | 4-12，1-2 行 | 18，2 行 | 24，2 行 |
| 章节引导语 | 12-30，最多 2 行 | 44，最多 3 行 | 60，最多 3 行 |

规则：章节页不放证据卡、流程步骤或四条以上要点。引导语不是摘要，超过 hard limit 时移到下一页 Key Message。

### 6.3 Key Message

**目的**：一页只表达一个可验证判断。

| 槽位 | recommended | soft limit | hard limit |
|---|---|---|---|
| 页面标题 | 6-16，最多 2 行 | 22，2 行 | 28，2 行 |
| 核心结论 | 14-34，最多 3 行 | 48，最多 4 行 | 64，最多 4 行 |
| 支撑说明 | 24-64，最多 4 行 | 90，最多 5 行 | 120，最多 6 行 |
| 来源标签 | 8-30，1 行 | 44，2 行 | 64，2 行 |

规则：核心结论必须绑定单一 Claim。`verbatim` 文本不能为适配容量而改写；超过 hard limit 时使用 continuation 页。

### 6.4 Evidence

**目的**：展示原文证据和来源，不追求高密度堆砌。

单卡版为 R1 主基线；双卡版只在单卡容量完成后标定。

| 槽位 | recommended | soft limit | hard limit |
|---|---|---|---|
| 页面标题 | 6-16，最多 2 行 | 22，2 行 | 28，2 行 |
| 证据标题 | 6-18，最多 2 行 | 26，2 行 | 34，3 行 |
| 原文正文 | 30-90，最多 6 行 | 130，最多 8 行 | 180，最多 10 行 |
| 来源名称 | 6-26，最多 2 行 | 40，2 行 | 56，3 行 |
| 版本/时间 | 8-28，1 行 | 40，2 行 | 52，2 行 |

规则：原文逐字符保持一致，禁止省略号替换和自动摘要。超过 hard limit 时按完整语义段分页，并在续页重复来源快照。来源元数据不能覆盖原文区域。

### 6.5 Process

**目的**：表达有限步骤及前后关系。

| 结构 | recommended | soft limit | hard limit |
|---|---|---|---|
| 步骤数量 | 3-5 | 6 | 7；超过即拆页 |
| 页面标题 | 6-16，最多 2 行 | 22 | 28 |
| 步骤标题 | 每步 2-8，最多 2 行 | 12 | 16 |
| 步骤说明 | 每步 10-26，最多 3 行 | 38，4 行 | 52，5 行 |
| 阶段编号 | 1-4 Unit | 6 | 8 |

规则：横向流程优先 3-5 步；6-7 步使用紧凑时间线或拆分；8 步以上禁止缩小为不可读流程。每个步骤绑定自己的 Claim，不允许一个绑定覆盖整条流程后自由改写步骤。

### 6.6 Closing

**目的**：收束结论和下一步，不重复整份方案。

| 槽位 | recommended | soft limit | hard limit |
|---|---|---|---|
| 收束标题 | 6-18，最多 2 行 | 24，2 行 | 32，3 行 |
| 行动建议 | 10-30，最多 2 行 | 44，3 行 | 60，3 行 |
| 补充说明 | 16-48，最多 3 行 | 70，4 行 | 90，5 行 |
| 联系/署名 | 每项 4-24，1 行 | 32 | 42 |

规则：Closing 不能新增未经前文验证的承诺或数字。神州数码 Logo 只有在官方素材已确认且场景允许时出现。

## 7. 每类页面需要的变体

R1 不导入更多模板，只在 Modern 骨架内完成容量需要的最小变体：

| 页面 | R1 变体 | 触发条件 |
|---|---|---|
| Cover | standard / long-title | 主标题超过 18 Unit |
| Section | standard / with-lead | 是否存在引导语 |
| Key Message | statement / statement-with-support | 是否存在支撑说明 |
| Evidence | single / continuation | 原文是否超过单页 hard limit |
| Process | 3-step / 4-5-step / continuation | 步骤数和单步容量 |
| Closing | takeaway / next-action | 收束结论或行动建议为主 |

这 12 个变体完成测量前，不新增 Executive、Momentum 或其他第三方模板。

## 8. 降级与分页决策表

| 情况 | 允许动作 | 禁止动作 |
|---|---|---|
| 超过 recommended | 使用标准换行或同类紧凑变体 | 立即缩小到最小字号 |
| 超过 soft limit | 分页或切换明确登记的长文变体 | 改写 verbatim 内容 |
| 超过 hard limit | 强制分页；不可分页时返回容量错误 | 截断、隐藏、缩放横向比例 |
| 字体缺字 | 切换受信中文字体并重新度量 | 依赖系统静默 fallback |
| HTML 通过、PPTX 溢出 | 以更保守的共同容量为准 | 两端使用不同正文 |
| 历史字号过小 | 保留层级比例，提升到本手册下限 | 机械复刻不可读字号 |

建议错误码：

- `TEMPLATE_CAPACITY_EXCEEDED`
- `TRUSTED_FONT_UNAVAILABLE`
- `HTML_PPTX_LAYOUT_DIVERGED`
- `UNBREAKABLE_TOKEN_OVERFLOW`
- `VERBATIM_REQUIRES_PAGINATION`

## 9. 标定产物

每个页面变体必须形成以下文件，才能被标记为 `measured`：

```text
capacity/<template_id>/<variant_id>/
  capacity.json
  cases.json
  html/
    recommended.html
    soft-limit.html
    hard-limit.html
    overflow-rejected.html
  screenshots/
    desktop-1600x900.png
    desktop-1440x900.png
    mobile-390x844.png
    powerpoint.png
    libreoffice.png
  report.json
```

`capacity.json` 必须冻结模板版本、字体哈希、Renderer 版本、槽位几何、三档容量和测量日期。任一依赖变化后原结果自动失效，必须重新标定。

## 10. 自动验收指标

- DOM 与视觉边界溢出均为 0 px；
- 元素不得进入底部 6% 安全区；
- 标题与正文间距不得低于本手册要求；
- recommended 样本活跃内容高度占页面 42%-82%；
- hard-limit 样本不得通过缩小到字号下限以下来适配；
- 文本节点内容哈希与输入一致；
- `verbatim` 文本逐字符一致；
- 数字、单位、日期和版本号保持不可拆分；
- HTML/PPTX 行数差不超过 1 行，关键区域不得出现几何重叠；
- 移动端只整体缩放固定画布，不重新排列事实内容；
- 截图必须人工检查，非空和无溢出不等于视觉合格。

## 11. 人工验收问题

每张边界截图至少由一名非开发成员回答：

1. 3 米投屏距离能否读清正文和来源？
2. 第一眼能否识别页面唯一主结论？
3. 留白是有设计感，还是内容显得残缺？
4. 中文断行是否自然，有没有孤字、标点悬挂或数字单位拆分？
5. 页面是否仍保留所选模板的层级和特色？
6. 换入历史 PPT 颜色后，层级和对比度是否下降？
7. HTML 与 PPTX 是否给人同一份作品的感觉？

任一问题被判定为严重失败，该容量档位不得发布。

## 12. R1 执行顺序

1. 引入并冻结一套可分发中文字体，记录许可证和哈希。
2. 冻结 Modern 的 12 个最小变体和槽位几何。
3. 建立与真实业务无关的中文边界语料。
4. 先测 Cover、Section、Closing 三类低密度页面。
5. 再测 Key Message、Evidence、Process 三类事实密集页面。
6. 用 `test1.pptx` 的颜色和字体类别做换肤复测。
7. 生成 HTML/PPTX 双产物和全套截图。
8. 回填 measured 容量，冻结 `ChineseCapacityProfile v1`。
9. 只有六类页面全部通过后，才开始导入第二套模板。

## 13. R1 退出条件

- 6 类页面、12 个变体均形成 measured 容量；
- 每个变体均覆盖 recommended、soft、hard 和 rejected 四类边界；
- 中文字体文件与许可已进入素材清单；
- HTML、PowerPoint、LibreOffice 和移动预览全部通过；
- Evidence 与 Process 的事实绑定和分页测试通过；
- `test1.pptx` 换肤后不降低对比度和可读性；
- 形成可供后续 Presenton 模板导入复用的容量字段规范、测试语料和验收脚本接口。

## 14. 后续模板导入标准流程

任何新模板都必须依次完成：

```text
模板来源与许可确认
→ 去除示例正文、图片和脚本
→ 映射六类页面槽位
→ 应用本手册字体与安全区
→ 跑同一份中文边界语料
→ 形成模板专属 measured 容量
→ HTML/PPTX/多视口截图
→ Golden Screenshot 人工确认
→ TrustedTemplateSnapshot
```

新模板不能直接继承 Modern 的字数结论，只能复用测量流程、语料、字段结构和验收门槛。
