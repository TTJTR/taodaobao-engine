# 生产部署说明

> 本文记录 `final` 比赛版本原有的公网云部署流程。当前
> `feat/local-deployment` 的根目录 `docker-compose.yml` 已切换为 Local First 拓扑，
> 请以 [本地部署说明](本地部署说明.md) 为准。若后续恢复公网域名、TLS 和云安全组，
> 应另建 Compose override，不要把云端默认重新写回本地基线。

## 前置条件

- Ubuntu 22.04/24.04 云服务器，建议至少 2 核 4 GB。
- 已安装 Docker Engine 与 Docker Compose Plugin。
- 域名 A 记录已指向服务器公网 IP。
- 安全组仅对公网开放 22、80、443，不开放 5432 和 8000。

## 首次部署

```bash
git clone git@github.com:wxh042/xianjintuan-engine.git
cd xianjintuan-engine
git switch --track origin/v2
cp .env.example .env
```

编辑 `.env`，至少替换以下值：

```dotenv
DOMAIN=ai.example.com
POSTGRES_PASSWORD=<openssl rand -hex 32 的结果>
APP_SESSION_SECRET=<openssl rand -hex 32 的另一结果>
APP_PUBLIC_BASE_URL=https://ai.example.com
APP_FRONTEND_REDIRECT_URL=https://ai.example.com/
```

真实密钥只写入服务器 `.env`，不得提交 Git。生产运行只接受 Live 配置；未配置的
AI、Embedding、飞书、互动 HTML 或公开情报 Provider 会明确显示 `not_configured`、
返回 503，或把异步任务标记为失败/跳过，不会生成模拟成功结果。

```bash
docker compose config
docker compose build --pull app worker
docker compose up -d
docker compose ps
```

`app` 容器每次启动会先执行 `alembic upgrade head`；`worker` 在 app 健康后启动，
领取数据库中的可信方案和演示长任务；Caddy 等待 app 健康后对外提供服务并自动申请 HTTPS。

## 验收

```bash
docker compose logs --tail=100 db app worker caddy
curl --fail --show-error "https://${DOMAIN}/api/v1/health"
curl --fail --show-error --head "https://${DOMAIN}/"
```

健康接口应返回 `service=ok`、`database=ok`。已配置服务返回 `ok` 或
`configured`，未配置服务返回 `not_configured`；不得出现 `mock`。同时
`workflow_queue.stale_leases` 应为 0。

## 更新发布

```bash
git fetch origin
git pull --ff-only origin v2
docker compose build --pull app worker
docker compose up -d
docker compose ps
```

若本次提交仅修改 Python 业务代码、静态前端和已有迁移，且服务器资源不足以重新构建
Docling 完整基础镜像，可以在一个已经通过验收的完整镜像上构建增量发布层：

```bash
docker build -f Dockerfile.incremental \
  --build-arg BASE_IMAGE=taodaobao-app:<上一完整镜像标签> \
  -t taodaobao-app:<新提交标签> .
```

增量镜像仍包含完整运行时，只复用上一完整镜像的依赖层。依赖、系统库、Node Sidecar 或
Dockerfile 发生变化时不得使用此方式，必须重新构建完整镜像。

发布前记录当前提交：

```bash
git rev-parse HEAD
```

需要回滚时切换到上一已验收提交并重新构建 app。数据库迁移是否允许降级必须逐条评审，
禁止在生产环境直接执行未验证的 `alembic downgrade`。

## 日志与备份

```bash
docker compose logs -f --tail=200 app worker
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' \
  > "backup-$(date +%Y%m%d-%H%M%S).sql"
```

备份文件应转存到服务器之外并限制访问权限。恢复操作必须先在测试环境演练。
## PPTX 导出运行时

> V2.0 比赛演示的正式交付形态是互动 HTML。以下 PPTX 运行时仅属于保留的历史兼容
> 能力，不是 V2.0 验收承诺；没有对应 Provider 时应跳过，不得使用 Mock 产物。

生产镜像包含固定 PptxGenJS 脚本和 Node 运行时。PPTX 写入 `presentation_exports` 共享卷，app 与 worker
挂载到 `/app/exports`。禁止用户指定 JavaScript、模板路径或任意图片 URL。

发布后运行：`docker compose exec -T worker node --check /app/sidecar/pptx-renderer/render.mjs`。
