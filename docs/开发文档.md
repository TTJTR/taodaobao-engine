## 3. 当前产品范围

V0.5 目标是跑通以下黄金流程：

```text
飞书登录或 Mock 登录
  -> 导入飞书文档或粘贴文本
  -> 提取客户画像、经验或原子能力草稿
  -> 人工修改和审核
  -> 创建客户会话并输入需求
  -> AI 提取结构化检索意图
  -> 数据库过滤、排序并形成 Top-K 检索快照
  -> AI 基于快照生成八区块方案
  -> 引用和事实边界校验
  -> 保存结果并支持多轮追问
```

当前阶段不实现向量数据库、Multi-Agent、Deep Research、知识图谱、自动建群、PPT 生成和复杂微服务基础设施。

- AI 结构化 Schema。

- 方案生成 Prompt 与生成算子。

### 4.3 AI 与服务端边界

- AI 不接收全量经验或能力列表。
- AI 通过 `extract_search_intent(context)` 返回结构化检索意图。
- Dev A 在数据库层完成工作空间隔离、状态过滤、硬约束过滤、排序和 Top-K 截断。
- Dev A 只向 `generate_solution` 传入最多 3 条经验和 5 条能力的固化快照。
- Molly 的算子遇到 LLM 错误时直接抛出 Python Exception。
- Dev A 在 AI Harness 捕获异常，执行重试、错误码转换和任务状态落库。

## 6. 已实现基础能力

### 6.1 FastAPI 应用入口

- 根目录 `main.py` 导出 ASGI `app` 和应用工厂 `create_app`。
- `app/main.py` 创建 FastAPI 应用、注册中间件、异常处理器和 V1 路由。
- 本地启动入口为 `uvicorn main:app --reload`。

### 6.2 统一响应

成功响应：

```json
{
  "request_id": "req_xxx",
  "data": {}
}
```

失败响应：

```json
{
  "request_id": "req_xxx",
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "服务暂时不可用",
    "retryable": true,
    "details": {}
  }
}
```

### 6.3 Request ID

- 优先透传请求 Header 中的 `X-Request-ID`。
- 请求未提供时生成 `req_<uuid>`。
- 响应体和 `X-Request-ID` 响应 Header 使用同一个值。

### 6.4 全局异常处理

- `AppError`：保留业务错误码、HTTP 状态、是否可重试和详情。
- `RequestValidationError`：转换为 `VALIDATION_FAILED`。
- 未处理 Exception：记录服务端日志，对外转换为 `INTERNAL_ERROR`，不泄漏异常堆栈。

### 6.5 幂等基础约束

- 所有 POST/PATCH 在 OpenAPI 中要求 `Idempotency-Key`。
- Key 长度为 16 至 128 个字符。
- 同一工作空间、用户和 Key 的幂等有效期为 24 小时。
- 同 Key、同请求指纹返回首次响应。
- 同 Key、不同请求指纹返回 `IDEMPOTENCY_KEY_CONFLICT`。
- 当前仅实现 Header 校验依赖，数据库持久化将在数据层阶段实现。

### 6.6 健康检查

当前接口：`GET /api/v1/health`。

当前返回：

```json
{
  "request_id": "req_xxx",
  "data": {
    "status": "ok",
    "service": "ok",
    "database": "not_configured",
    "ai": "mock"
  }
}
```

这表示 FastAPI 服务可运行，但数据库尚未配置，AI 当前为 Mock 模式。

### 2026-08-07 / DEV-024：AI Harness 重试、校验与失败边界

- 执行人：Codex，协助 Dev A。
- 目标：在系统编排与 AIEngine 之间建立稳定容灾外壳，将模型异常转换为可轮询、可恢复的 SolutionRun 状态。
- 架构决定：
  1. AIHarness 依赖注入 `AIEngine + AsyncSession + workspace_id`，不直接访问全量资产；输入仅为会话上下文和系统层生成的 Top-K RetrievalSnapshot。
  2. AI 调用默认首次执行加最多 2 次重试，采用有限指数退避；捕获标准 Python Exception，但不捕获取消等 BaseException。
  3. 超时、网络、JSON/结构错误或其他 Engine 异常耗尽后不向 BackgroundTask 外抛出，统一落 `failed/MODEL_TEMPORARILY_UNAVAILABLE/retryable=true/completed_at`。
  4. Retrieval/数据库/消息编排异常不伪装成模型错误，仍由 Pipeline 落 `INTERNAL_ERROR`。
  5. 成功结果必须是 JSON object，且八个必需区块全部存在并为数组；缺区块或类型错误进入相同有限重试与降级流程。
- 实际操作：
  1. 将 `v1需求.zip` 和 `v1需求/` 精确加入 `.gitignore`，不删除本地资料、不纳入 V0.5 提交。
  2. 新增完整实现 AIEngine Protocol 的 `MockAIEngine`，将原 Pipeline 的八区块硬编码移入可替换 Adapter。
  3. 新增 `AIHarness.run_solution_generation`，实现重试、日志、结构校验和失败状态持久化；失败状态落库本身异常时执行回滚并记录日志，不二次抛出。
  4. 在 `app/api/deps.py` 根据 `APP_AI_MODE` 注入 MockAIEngine；live 模式缺少真实 Engine 时明确报配置错误，不静默降级。
  5. turns 路由将 AIEngine 传给 BackgroundTask；Pipeline 在自己的数据库 Session 内构造 Harness，检索快照在 AI 调用前绑定 Run，成功后继续落结果和 assistant 消息。
- 测试：覆盖前两次超时第三次成功、持续网络错误耗尽后失败落库、不完整八区块结果重试与降级，以及重构后的 Pipeline 成功闭环。

### 2026-08-07 / DEV-023：会话、原生检索与快速方案黄金闭环

- 执行人：Codex，协助 Dev A。
- 目标：实现 Session/Message 持久化、PostgreSQL 原生 Top-K 检索、独立 SolutionRun 轮询和前端八区块方案展示。
- 架构决定：
  1. SolutionRun 是方案生成唯一状态对象，不进入 Job 系统；`pending/running/completed/failed` 与冻结契约一致。
  2. BackgroundTasks 只接收 `run_id/workspace_id`，内部创建独立 AsyncSession，避免复用请求级数据库连接。
  3. 消息 sequence 在工作空间与会话级 advisory lock 内读取最大值并递增，数据库 `(session_id, sequence)` 唯一约束继续兜底。
  4. Retrieval 只读取当前 workspace、`verified`、未软删除资产；文本 `ILIKE` 用作排序加权，无命中时按更新时间降级，严格截断经验 3 条、能力 5 条。
  5. RetrievalSnapshot 将 UUID、更新时间和 JSONB data 复制为独立 JSON，后续资产软删除不会影响历史方案展示。
- 实际操作：
  1. 扩展 SessionRepository 和 MessageRepository，实现画像过滤分页、消息按 sequence 恢复和下一个序号计算。
  2. 新增 `SessionService`，实现绑定画像创建会话、列表、详情消息恢复，以及用户消息与 pending SolutionRun 同事务创建。
  3. 新增 `RetrievalService`，使用 SQLAlchemy/PostgreSQL JSONB 文本匹配与更新时间排序，无向量库、无全库灌入 AI。
  4. 新增 `run_solution_pipeline`：模拟 2 秒处理，落检索快照、8 区块 Mock Solution、completed 时间和 assistant Message；异常统一落 failed。
  5. 新增 Sessions 与 SolutionRuns 薄 Router，写接口启用 `IdempotencyRoute` 并强制 `Idempotency-Key`。
  6. 前端登录并行加载会话；创建、选择和恢复会话改为真实 API；quickSearch 提交 turn、轮询 SolutionRun，并渲染需求理解、初步建议、历史依据、能力组合、前置风险、待确认项、来源和建议追问八区块。
- 测试：覆盖检索硬过滤与 Top-K、turn 创建、Pipeline 完成与 assistant 消息、路由挂载和前端 Adapter 标记。
- 数据库：使用现有 Session/Message/SolutionRun 表和约束，本阶段不修改模型；提交前执行 `alembic check`。
- 当前限制：Pipeline 仍是 Mock 方案编排，下一阶段由 AI Harness 替换 `_build_mock_solution`；BackgroundTasks 不提供进程崩溃恢复，生产化需持久化 Worker 扫描 pending/running Run。
