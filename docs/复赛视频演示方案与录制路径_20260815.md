# 淘到宝引擎复赛视频演示方案与录制路径

建议时长：4 分 30 秒。叙事主线不是逐页点功能，而是完整走过一次“磋商前—磋商中—磋商后”。

## 录制前准备

1. 使用隔离的比赛演示 workspace；
2. 预先导入并校验内置虚构文档，确认索引报告 `status=passed`；
3. 建立一份已确认客户画像和一个快速方案会话；
4. 预跑一次情报/招标、演练、Deep Research 与互动 HTML，避免录屏等待；
5. 飞书准备一个测试用户，确保 OAuth、文档权限和机器人建群权限有效；
6. 开启浏览器无痕或清理旧本地存储，避免旧原型数据混入画面。

## 分镜与讲述

### 0:00–0:25 问题与一句话方案

画面：飞书登录 → 今日工作台。

讲述：售前资料散落、方案依赖个人经验、公开情报难验证。淘到宝把一次磋商拆成前中后三段，并让每条结论有来源、有边界、能回到飞书协作。

### 0:25–1:20 磋商前：看清客户和项目

画面：情报与招标 → 情报来源 → 画像 Proposal → 招标响应矩阵。

重点：公开信息只形成建议，员工确认后才进入长期画像；招标要求逐项对应企业经验/能力，缺少依据就拦截，不补写承诺。

### 1:20–2:15 磋商中：快速回应与异议预演

画面：快速方案 → 运行结果 → 来源和风险 → 方案演练。

重点：经验与原子能力分库检索；展示 `historical_fact`、`enterprise_capability`、`ai_inference`、`pending_confirmation` 四种边界；演练客户异议并记录知识缺口。

### 2:15–2:55 互动 HTML：把可信方案变成抓眼球的交付

画面：演示交付 → 互动 HTML 预览 → 点击交互组件。

重点：AI负责页面表达，但不得改写事实；HTML 生成后仍通过 FactBinding 与安全审计。V2.0 不把 PPTX 作为核心承诺。

### 2:55–3:45 磋商后：复杂问题和专家协作

画面：Deep Research 阶段进度 → 知识缺口 → 发起专家协作 → 飞书群首条研究概述。

重点：Multi-Agent 只用于复杂研究；系统只推荐真实贡献者；员工确认后才建群；回复回流同一研究任务，不能自动成为已校验经验。

### 3:45–4:15 可信底座与可验证结果

画面：资料中心 → 内置样例文档 → 经验/能力详情 → AI 运行与模型连接。

重点：展示索引命中标题、来源快照、审核版本与权限状态；未配置的服务明确显示“未配置”，不会用 Mock 冒充成功。

### 4:15–4:30 收束

画面：返回今日工作台。

结语：公开情报发现机会，可信资产支撑回答，研究和专家补齐未知，最终把每次磋商沉淀为下一次可复用的企业能力。

## 失败时的真实处理

- Provider 临时不可用：保留错误提示，切换到已完成的真实历史任务，不口述“正在实时生成”。
- 飞书回调失败：展示已成功的真实群与研究文档，再说明当前录制不重复建群。
- 自动情报未配置：明确说当前采用已入库情报和手工来源，不展示伪造搜索结果。
- 索引验收未通过：不要录制快速方案成功画面，先修复数据库/Embedding。

## 建议最终截图

- 今日工作台的三阶段主线；
- 招标响应矩阵中的“有依据/依据不足”；
- 快速方案的来源与四类事实边界；
- 互动 HTML 的一个交互页面；
- Deep Research 到飞书群的回流；
- 内置文档索引报告的四条真实命中。
