# 项目结构与维护约定

## 目录职责

| 路径 | 职责 | 是否属于运行时核心 |
|---|---|---|
| `app/` | FastAPI、领域服务、数据访问、AI Harness、外部集成与 Worker | 是 |
| `alembic/` | PostgreSQL Schema 迁移 | 是 |
| `static/` | 当前本地产品前端 | 是 |
| `sidecar/` | 可选外部能力包装服务和 PPTX 渲染器 | 条件启用 |
| `scripts/` | 本地启停、备份、导入、验收和历史演示工具 | 部分 |
| `tests/` | 自动化测试 | 否，交付质量基础 |
| `docs/product/` | 分版本 PRD 和需求追溯 | 否，产品基线 |
| `docs/test-reports/`、`evals/` | 验收证据 | 否，质量证据 |
| `portfolio/` | 开发和产品求职展示材料 | 否 |
| `examples/`、`fixtures/` | 示例与测试输入 | 否 |

## 根目录文件

- `docker-compose.yml`：Local First 正式编排入口。
- `compose.dev.yaml`：非容器化开发时的依赖服务入口。
- `Dockerfile`、`start.sh`、`Caddyfile.local`：Local First 镜像和容器入口。
- `Dockerfile.incremental`、`Caddyfile`：历史云端增量部署入口，保留用于兼容和迁移。
- `.env.example`：配置模板；真实 `.env` 只存在本机。
- `openapi.yaml`：冻结 HTTP 契约。
- `pyproject.toml`、`uv.lock`：Python 项目和依赖锁定。
- `邀请码生成器.ipynb`：历史邀请机制辅助工具，不属于默认本地启动链路。

## 新增内容放置规则

- 业务代码放到对应的 `app/` 分层，不在根目录新增临时脚本。
- 可复用运维脚本进入 `scripts/`；一次性调试文件不提交。
- 新 PRD 进入 `docs/product/<version>/`，并更新版本索引和 `docs/README.md`。
- 测试报告进入 `docs/test-reports/` 或 `evals/`，不要把日志原文提交为报告。
- 示例必须标明虚构属性，并走真实业务数据结构和处理流程。
- 本地缓存、模型文件、上传、导出、备份和日志必须保持 Git 忽略。

## 变更门禁

1. 修改前检查分支与 `git status`，保留其他成员未提交内容。
2. 不擅自修改已有 HTTP 路径、字段语义、状态枚举或五个 `AIEngine` 方法签名。
3. 修改数据库结构必须增加 Alembic 迁移，不能要求用户手工建表。
4. 外部服务必须可选；未配置时返回真实不可用状态，不生成 Mock 成功。
5. 只运行与开发中改动相关的测试；形成正式交付时再运行全量回归。
6. 提交前至少检查格式、Compose 配置、迁移状态、健康接口和冻结契约差异。

## 文档优先级

当说明不一致时，按以下顺序判断并记录冲突：冻结契约 → 最新增量契约 → 当前版本最终 PRD → 当前实现与迁移 → 测试证据 → 历史比赛材料。代码若与冻结契约冲突，先报告，不自行重写契约。
