# 淘到宝引擎 V2 分支上传与接力规范

## 1. 分支角色

- `main`：只放已经验收、可部署的稳定版本，不直接开发。
- `8.11_backbone`：2026-08-11 的 V1.1 集成基线，不再往其中混入 V2 开发提交。
- `v2_backbone`：V2 后台与业务后端的集成分支，也是 V2 两位开发人员共同接力的起点。
- `feat/<模块>-<姓名或缩写>`：开发人员自己的功能分支，例如 `feat/v2-intelligence-xy`、`feat/v2-rehearsal-wxh`。
- `<日期>_backbone`：只有产品负责人完成集成验收后创建，例如 `8.14_backbone`。开发人员不得自行把功能分支命名为新的日期基线。

## 2. 开始开发

开发人员只需先读本模块 PRD、增量契约和交接说明，不要求每次把整个仓库文档全部喂给 Codex。

```bash
git fetch origin
git switch v2_backbone
git pull --ff-only origin v2_backbone
git switch -c feat/v2-<module>-<name>
```

必须读取：

1. `docs/openapi-v2-incremental.yaml`
2. `docs/V2后端实现与联调说明.md`
3. 自己负责模块的 V2 PRD
4. 涉及旧接口时再读取根目录 `openapi.yaml` 和 `app/contracts/ai.py`

## 3. 提交规则

一次提交只解决一个可说明的问题，禁止把无关格式化、个人配置、运行日志和密钥一起提交。

推荐提交信息：

```text
feat(v2-intelligence): add provider adapter
fix(v2-rehearsal): reject duplicate answered turn
test(v2-tender): cover stale evidence rejection
docs(v2): clarify response matrix contract
```

提交前执行：

```bash
uv sync --all-extras
uv run ruff check app tests alembic
uv run pytest -q
git diff --check
git status --short
```

严禁提交：

- `.env`、API Key、飞书 App Secret、服务器私钥或数据库密码；
- `.venv`、缓存、临时测试产物；
- 未经授权修改已有路径、字段语义、状态枚举和五个 `AIEngine` 方法签名；
- 用固定结果伪装真实接口；Mock 必须与真实 Schema 相同并明确标记。

## 4. 上传功能分支

```bash
git push -u origin feat/v2-<module>-<name>
```

Pull Request 的目标分支必须是 `v2_backbone`，不能直接指向 `main` 或旧的 `8.11_backbone`。PR 描述必须包含：

- 实现了什么；
- 修改了哪些接口或表；
- 上下游依赖；
- 测试命令与结果；
- 未完成项、已知风险和 Mock 边界；
- 是否涉及迁移、环境变量或部署步骤。

## 5. 集成与日期基线

产品负责人依次执行：

1. 在 `v2_backbone` 拉取最新代码；
2. 逐个合并已审核 PR，出现冲突时由对应模块作者解释语义；
3. 从空数据库执行 `alembic upgrade head`；
4. 跑全量测试和契约检查；
5. 部署测试环境并完成线上冒烟；
6. 验收通过后，从 `v2_backbone` 创建当天的 `<日期>_backbone`；
7. 再由产品负责人决定是否合并到 `main` 作为部署版本。

日期基线只表示“当天已经集成验收的快照”，不是普通开发分支。

## 6. 冲突处理原则

优先级从高到低：

1. 冻结 `openapi.yaml` 和 `app/contracts/ai.py`；
2. 最新已确认 V2 PRD与 `openapi-v2-incremental.yaml`；
3. `v2_backbone` 已通过测试的实现；
4. 功能分支自己的实现。

遇到契约冲突先停止合并并记录，不允许为了让代码运行而自行改变接口语义。
