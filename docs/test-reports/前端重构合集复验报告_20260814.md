## 2. 未通过项

### BUG-FE-001：移动端侧栏被遮罩层覆盖，导航不可点击

- 严重程度：S1
- 复现环境：390×844，飞书原生主题；共享 CSS/JS，因此影响全部五套主题。
- 复现步骤：点击移动菜单按钮，再点击“资料与知识”。
- 实际结果：侧栏从左侧出现，但整个侧栏同时被模糊遮罩覆盖；点击被 `#overlay` 截获，URL 仍为 `#team`，标题仍为“关于我们”，未进入“资料与知识”。
- 根因：`.sidebar` 的 `z-index:30`，`.overlay.open` 的 `z-index:39`，遮罩位于移动侧栏上方。
- 补充问题：遮罩点击只调用 `closeDrawer()`，不会关闭移动侧栏。
- 说明：旧的 `测试结果.md` 声称“移动端菜单按钮可以打开导航”，但只验证了侧栏位移，没有验证导航真正可点击；本次真实点击复验推翻该结论。
- 关闭条件：侧栏层级高于背景遮罩；点击导航可切换页面并自动关闭侧栏；点击侧栏外遮罩可关闭侧栏。

### GAP-FE-001：API 适配器没有被业务页面使用

- 严重程度：S1（联调阻断）
- `window.TDB_API` 只在 `shared/api-adapter.js` 中定义，`shared/app.js` 没有任何调用。
- 将 `mode` 从 `prototype` 改成真实模式并不会让页面读取后端；所有列表、指标、方案、研究、情报、招标和演练仍来自 `shared/data.js` 或写死的渲染字符串。
- 关闭条件：逐页面建立真实 API 调用、加载/空态/错误态/权限态和写操作幂等处理，Mock 与真实接口使用同一 Schema。

### GAP-FE-002：V2 接口路径与实际后端不一致

- 严重程度：S1（联调阻断）
- 原型当前配置：`/api/v2/intelligence`、`/api/v2/tenders`、`/api/v2/rehearsals`。
- 当前 V2 后端约定：增量能力统一位于 `/api/v1`，情报和招标拥有更细粒度的 search-runs、items、proposals、response-matrices 等路径。
- 影响：即使启用真实模式，也无法按当前路径完成 V2 联调。
- 关闭条件：以 V2 增量契约和现有后端实际路由重建 API client，不得自行修改后端路径来迁就原型。

### GAP-FE-003：产品信息架构仍是“功能模块”，未采用最新磋商场景主线

- 严重程度：S2（产品叙事与演示阻断）
- 当前主导航：资料与知识、客户画像、快速方案、Deep Research、专家协作、情报与招标、方案演练、演示交付、AI 运行。
- 最新确认的业务主线：
  - 磋商前：情报搜集、画像补全、会前简报、异议预演；
  - 磋商中：现场问题、可信检索、快速方案、风险和待确认项；
  - 磋商后：妙记同步、Deep Research、专家协作/招标响应、深度方案和复盘沉淀。
- 影响：评委看到的是功能菜单，不能第一时间理解系统如何陪伴一次真实客户磋商。
- 建议：工作台首先展示“本次磋商”的前/中/后阶段和下一动作；资料库、可信底座、AI 运行保留为二级能力或后台支撑。

### GAP-FE-004：交互按钮大多仍是展示行为

- 严重程度：S2
- 快速方案、建群、情报 Proposal、招标响应、演练报告、演示保存等操作目前使用 drawer/toast 或原型字符串模拟。
- 页面对此已有原型标记，因此不构成欺骗，但不能作为真实功能验收通过的证据。

## 3. 验收结论

### 视觉方案选择

**通过。** 五套风格足以用于确定视觉方向，“飞书原生为业务基线，商业杂志/架构蓝图用于展示和复杂数据表达”的组合建议仍然合理。

### 正式前端交付

**不通过。** 当前仍是高保真 Prototype，不是已经接通 V2 后端的正式前端；移动端主导航还存在阻断性缺陷。

## 4. 推荐顺序

1. 修复移动侧栏层级、关闭逻辑和真实导航回归。
2. 按“磋商前—磋商中—磋商后”重组首页与演示主路径。
3. 以飞书原生主题作为唯一正式业务基线，避免维护五套生产皮肤。
4. 按真实 `/api/v1` 增量契约实现 API client，逐模块替换 `shared/data.js`。
5. 增加自动化浏览器测试：桌面/移动导航、API 错误态、快速方案、Deep Research、情报 Proposal、招标审核和演练报告。
