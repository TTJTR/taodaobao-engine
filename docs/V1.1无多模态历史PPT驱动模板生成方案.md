# V1.1 无多模态历史 PPT 驱动模板生成方案

## 1. 文档状态

- 版本：V1.0 Draft
- 日期：2026-08-11
- 范围：V1.1 历史 PPT 风格驱动 HTML/PPTX
- 不包含：组长下发的产品 V2 需求、多模态模型、自由生成布局、在线模板市场
- 当前结论：先用确定性 OOXML 解析和 Presenton 成熟模板完成一条高质量纵向链路，再决定是否增加多模态风格识别。

## 2. 目标与非目标

### 2.1 业务目标

输入一份已经通过审核的方案和用户选择的历史 PPTX，系统自动生成：

1. 具有历史 PPT 主要颜色、字体气质和版式倾向的中文 HTML 演示稿；
2. 与 HTML 视觉一致的可编辑 PPTX；
3. 所有业务事实仍可追溯到原方案的 Claim、Evidence 和 Source；
4. 在没有历史 PPT 或解析质量不足时，使用成熟默认模板，而不是退回简单色块排版。

### 2.2 本阶段非目标

- 不使用视觉语言模型理解页面截图。
- 不追求逐像素复刻原 PPT。
- 不复制原 PPT 的客户名、数字、正文、图片或图表数据。
- 不允许 AI 输出 CSS、HTML、坐标或任意模板代码。
- 不强制给客户演示稿添加神州数码 Logo。
- 不在运行时从零设计页面。

## 3. 为什么不需要先上多模态模型

当前影响效果的首要问题不是“模型看不懂 PPT”，而是运行时缺少成熟模板选择、中文模板、设计令牌映射和视觉质量门禁。OOXML 已能稳定提供：

- Theme 和 Master 中的主题色、背景色、字体族；
- 内页脱敏后的坐标、尺寸、字号、填充、边框和页面密度；
- 常用布局占比，例如封面、标题正文、双栏、卡片阵列和大图页；
- 页面比例、留白范围和装饰色使用频率。

这些数据足以完成“选择成熟模板并换肤”的 MVP。多模态模型更适合后续识别隐性的视觉语义，例如极简、科技、杂志、正式、活泼等，但它不应替代模板系统。

## 4. 推荐总体架构

```text
历史 PPTX
  ↓
SafePPTXParser
  ├─ Theme/Master 精确解析
  └─ sanitized_visual 脱敏几何统计
  ↓
StyleFingerprint
  ↓
StyleTokenMapper
  ↓
TemplateSelector ───── PresentationAssetCatalog
  ↓                         ├─ Presenton 模板
SelectedTemplate            ├─ 中文字体
  ↓                         └─ 装饰与品牌包
SlidePlan + FactBinding
  ↓
TemplateSlotFiller
  ↓
Schema Validation + FactBinding Validation
  ↓
PositionedSpec
  ↓
Final EvidenceGuard
  ↓
Deterministic HTML Renderer / PPTX Renderer
  ↓
VisualQualityGate + Golden Screenshot
```

核心变化是：`Layout Engine` 不再从零计算页面，而是从成熟模板目录选择页面变体，只对内容槽位做确定性填充、分页和字号级别调整。

## 5. 直接借鉴 Presenton 的范围

### 5.1 可迁移设计

- Template v2 的 Element、Container、Grid、Vector、Fill、Stroke、Shadow 结构；
- 模板由多个页面变体组成，而不是一套万能布局；
- JSON Template 到 HTML 的确定性渲染方式；
- 模板缩略图、字体和静态装饰的目录组织；
- `executive`、`modern`、`momentum` 的成熟页面骨架和视觉层级；
- 模板级画布、字体和装饰资源管理方式。

### 5.2 不能直接复制的部分

- 英文示例内容、示例人物照片和业务图片；
- 依赖英文字符宽度的固定字号与文本容量；
- 与本项目 FactBinding、EvidenceGuard 不兼容的数据结构；
- 图片生成、用户系统、MCP、云部署等无关模块；
- 允许任意文本或任意代码进入模板的接口。

### 5.3 迁移方式

不直接运行原始 Template JSON。先经过一次离线导入：

```text
Presenton Template v2
→ TemplateSanitizer
→ 中文槽位改造
→ 容量标注
→ Golden Screenshot 人工确认
→ TrustedTemplateSnapshot
```

只有形成 `TrustedTemplateSnapshot` 的模板才能被线上选择。

### 5.4 双 Skill 与 Presenton 的协作方式

本项目同时使用 `guizang-ppt-skill` 和 `frontend-slides`，但它们不是线上运行时依赖：

| 能力 | 定位 | 本项目采用内容 | 不采用内容 |
|---|---|---|---|
| guizang-ppt-skill | 离线模板设计与中文视觉验收 | 杂志/瑞士风设计语言、锁定布局、主题节奏、中文字号、溢出/留白/标题间距校验思想 | WebGL、CDN、演讲者 JS 不直接进入受信 Renderer |
| frontend-slides | 离线多视口质量规范 | 固定画布、禁止页内滚动、内容密度、桌面/移动截图、降低动效模式 | 不把自由单 HTML 生成作为线上事实渲染器 |
| Presenton | 线上模板结构与确定性渲染基线 | Template v2、Element Tree、布局变体、JSON-to-HTML/PPTX 思路 | 示例业务内容、图片生成和无关系统模块 |
| 本项目可信链 | 事实与审计边界 | FactLedger、FactBinding、EvidenceGuard、资产清单、不可变快照 | 不允许模板或 Skill 修改业务事实 |

离线模板生产流程调整为：

```text
Presenton Template v2
  + guizang 中文布局与主题节奏
  + frontend-slides 多视口规范
→ 中文模板原型
→ 两套 Skill 的视觉检查
→ 去除脚本、网络和示例事实
→ 转换为本项目受限 Template Schema
→ Golden Screenshot 人工评审
→ TrustedTemplateSnapshot
```

`guizang-ppt-skill` 当前安装版本固定到
`op7418/guizang-ppt-skill@c91369c449d34755d320a8b81d0734000d99d1ab`，许可证为
AGPL-3.0。它可以作为开发技能运行和设计参考；如需复制模板、CSS、JavaScript 或校验脚本进入产品仓库，必须先完成 AGPL 合规评审。MVP 优先迁移其设计规则、布局参数和测试指标，不直接复制受 AGPL 约束的实现代码。

## 6. StyleFingerprint 设计

`StyleFingerprint` 是历史 PPT 的确定性风格指纹，不包含业务文本。

```yaml
schema_version: style-fingerprint-v1
canvas:
  aspect_ratio: 1.7778
palette:
  background: "#FFFFFF"
  foreground: "#111827"
  primary: "#1D4ED8"
  secondary: "#0F766E"
  accent: "#EF3E42"
  neutral: ["#F3F4F6", "#D1D5DB", "#6B7280"]
typography:
  source_heading_font: "等线 Light"
  source_body_font: "等线"
  heading_body_ratio: 1.65
  body_size_px: 24
  weight_contrast: high
geometry:
  outer_margin_ratio: 0.055
  title_band_ratio: 0.12
  column_gap_ratio: 0.025
  content_density: medium
layout_distribution:
  cover: 0.08
  title_body: 0.28
  two_column: 0.22
  card_grid: 0.18
  image_focus: 0.12
  section: 0.12
decoration:
  corner_radius: low
  border_usage: medium
  shadow_usage: low
  accent_position: right_edge
confidence:
  theme: 0.95
  typography: 0.82
  geometry: 0.76
```

解析结果需要记录字段来源与置信度。低置信度字段不得覆盖成熟模板默认值。

## 7. 模板选择算法

每套受信模板必须具有 `TemplateDescriptor`：

- 支持的页面 archetype；
- 支持的内容密度；
- 布局倾向；
- 圆角、边框、阴影和装饰特征；
- 中文文本容量；
- 可替换的颜色与字体 token；
- 是否支持图片、图表、指标和流程；
- Golden Screenshot 评分。

选择分数采用确定性加权：

```text
score =
  0.30 × layout_coverage
  + 0.20 × density_similarity
  + 0.15 × geometry_similarity
  + 0.15 × typography_compatibility
  + 0.10 × decoration_similarity
  + 0.10 × golden_quality_score
```

颜色不作为主要模板选择因素，因为颜色可通过 token 换肤。页面类型覆盖率和内容容量必须优先，否则即使配色相似也会产生低质量排版。

MVP 不让用户只看到一个答案。系统对同一方案生成前三名模板的封面、证据页和流程页预览，用户确认后再生成全稿。

## 8. 颜色映射与质量保护

### 8.1 角色映射而非字符串替换

历史 PPT 的颜色需要先归类为视觉角色：

- `surface.canvas`
- `surface.panel`
- `text.primary`
- `text.secondary`
- `brand.primary`
- `brand.secondary`
- `accent.critical`
- `border.subtle`

模板只引用角色 token，不直接写死历史 PPT 的颜色值。

### 8.2 对比度门禁

- 正文与背景对比度不低于 WCAG AA 4.5:1；
- 大标题不低于 3:1；
- 图表序列色需要有足够色差；
- 历史颜色不合格时允许调整明度和饱和度，但保持色相与品牌识别；
- 自动调整必须记录原值、调整值和原因。

### 8.3 保真边界

“学习历史风格”不等于机械复制低质量颜色。系统优先保持品牌色相、冷暖关系和主辅色占比，同时允许为可读性修正明度。

## 9. 中文字体映射与排版保护

### 9.1 中文字体库

素材库需要补充许可清晰、可随产物分发的中文字体，建议首批：

- 思源黑体：现代、科技、商务正文；
- 思源宋体：报告、叙事、正式内容；
- 霞鹜文楷或其他 OFL 字体：仅用于少量特色标题，不作为正文默认值。

现有 Anton、Montserrat 等拉丁字体只能用于数字和英文强调，不能承担中文正文。

### 9.2 字体映射

历史字体若存在于受信字体库，则使用同一字体；否则根据类别映射：

```text
中文无衬线 → 思源黑体
中文衬线   → 思源宋体
几何英文   → Montserrat
窄体强调   → Anton，仅限英文或数字
```

### 9.3 不降质规则

- 使用真实 OpenType glyph metrics 计算中文宽度；
- 不依赖浏览器临时 fallback；
- 每个槽位定义中文字符容量，而非沿用英文容量；
- 自动调整顺序固定为：换行 → 更紧凑模板变体 → 分页 → 有限字号降级；
- 低于模板最小字号仍无法容纳时必须失败，Renderer 不允许截断事实。

## 10. 中文语义模板集

第一批不追求模板数量，而是把以下页面做成熟：

| 页面类型 | 必需变体 | 主要用途 |
|---|---:|---|
| Cover | 3 | 客户名、方案名、日期 |
| Agenda | 2 | 八区块目录、章节导航 |
| Section | 3 | 章节过渡 |
| Key Message | 3 | 核心判断、机会或痛点 |
| Evidence | 4 | 原文、来源、证据说明 |
| Metric | 3 | 已验证数字与单位 |
| Comparison | 3 | 现状与目标、方案对比 |
| Process | 3 | AI for Process 流程 |
| Architecture | 2 | 分层架构和系统关系 |
| Roadmap | 3 | 阶段计划和里程碑 |
| Closing | 2 | 总结和下一步 |

每个页面变体必须声明槽位类型、容量、是否需要 FactBinding、允许的图片比例和最小字体。

## 11. 神州数码品牌素材的定位

品牌包不是所有客户演示稿的强制皮肤，使用策略如下：

1. 用户上传历史 PPT：客户风格优先，神州数码 Logo 仅在联名或署名开关开启时出现；
2. 无历史 PPT：使用神州数码默认品牌模板；
3. 神州数码内部汇报：使用完整品牌包；
4. 品牌原件未确认：使用纯文本署名，不生成近似 Logo。

品牌包应包含官方 Logo、主辅色、留白规范、禁用规则和推荐中英文字体。当前官网不可访问，必须等待官方文件后才进入运行时。

## 12. 与现有事实安全链路的关系

视觉效果优先不代表删除事实边界。模板选择和换肤不需要读取或修改事实，因此可以保留：

```text
SlidePlan
→ Schema Validation
→ FactBinding Validation
→ Template Selection / Slot Filling
→ PositionedSpec
→ Final EvidenceGuard
→ Renderer
```

Renderer 只能读取已经定位的元素和受信资产，不得：

- 修改正文、数字或单位；
- 生成补充解释；
- 改写 Claim；
- 从模板示例内容中补全业务字段；
- 调用 LLM；
- 因溢出而静默删字。

## 14. 分阶段实施

### R1：六类中文页面容量标定

- 只使用 `Modern` 作为测量骨架，不导入第二套模板；
- 为 Cover、Section、Key Message、Evidence、Process、Closing 建立最小必要变体；
- 冻结中文字体文件、槽位几何以及 recommended、soft、hard 三档容量；
- 使用纯中文、中英混排、数字单位、长标题和不可拆分 token 等边界语料逐级测量；
- `test1.pptx` 仅用于颜色和字体类别换肤复测，不用于增加模板类型；
- 输出 HTML、PPTX、桌面/移动截图和容量报告；
- 具体规则以 `docs/中文模板改造手册.md` 为准。

退出条件：6 类页面的 12 个最小变体均形成 `measured` 容量；HTML、PowerPoint、LibreOffice 和移动预览无溢出、重叠、缺字或事实变化；换肤后对比度和层级不下降。达到该条件后才允许导入第二套模板。

### R2：三模板选择

- 接入 Executive 和 Momentum；
- 完成 `TemplateDescriptor` 和选择算法；
- 对 `test1/test2/test3.pptx` 分别生成前三名预览；
- 验证模板选择稳定、颜色映射合理。

退出条件：相同输入重复选择结果一致；至少 80% 的测试页面无需退回简单系统模板。

### R3：完整中文页面集

- 扩展到第 10 节的全部页面类型；
- 增加中文字体库和打包；
- 建立分页与长文本变体；
- HTML/PPTX 双输出对齐。

退出条件：Golden Set 无溢出、无缺字、HTML/PPTX 关键几何差异在容许范围内。

### R4：生产门禁

- 模板快照、资产哈希和 Renderer 版本入库；
- 加入并发、性能、浏览器和 Office/LibreOffice 兼容测试；
- 保留旧 Renderer 灰度回退；
- 人工确认后再切换主产物。

## 15. 测试方案

### 15.1 单元测试

- StyleFingerprint 不含历史业务文本；
- 同一 PPTX 生成相同指纹；
- 颜色角色映射和对比度修正；
- 模板选择评分与稳定排序；
- 中文字体映射、字符容量和分页；
- 未确认资产不能进入受信模板；
- Renderer 不修改绑定文本和数字。

### 15.2 集成测试

- `PPTX → Fingerprint → Template → HTML`；
- `SlidePlan → FactBinding → PositionedSpec → EvidenceGuard`；
- 同一 PositionedSpec 的 HTML/PPTX 双输出；
- 模板或字体哈希改变时快照校验失败。

### 15.3 视觉测试

- 固定 1600×900 逻辑画布；
- 浏览器桌面 1440×900、1920×1080；
- 移动预览 390×844，整页缩放而非重新排版；
- 每页 `overflow=hidden`，但任何内容不得被裁切；
- 检测空白率、元素重叠、标题距离、底部留白、图片比例和文本可读性；
- Golden Screenshot 做像素差异检测，同时保留人工视觉评分。

### 15.4 真实样本验收

对 `test1.pptx`、`test2.pptx`、`test3.pptx` 输出：

- 风格指纹 JSON；
- 选中的模板和评分解释；
- 封面、证据、流程三页候选预览；
- 完整 HTML；
- 完整 PPTX；
- 桌面和移动截图；
- 事实一致性与视觉质量报告。

## 16. MVP 成功标准

- 所有最终业务文本来自 SlidePlan/FactLedger，模板零示例文本泄漏；
- 所有数字逐字符一致；
- 中文字体真实打包，无缺字和不可控 fallback；
- 三份测试 PPT 均能选出成熟模板并完成换肤；
- 颜色对比度全部通过；
- HTML 和 PPTX 无明显溢出、重叠或裁切；
- 至少覆盖 10 种企业常用页面类型；
- 人工盲评中，新版本相对当前简单 Renderer 的偏好率不低于 80%；
- 单份 20 页演示稿的模板选择和渲染时间满足 MVP 联调要求。

## 17. 关键风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 原 PPT 母版不规范 | 风格指纹不完整 | 使用 sanitized_visual 聚合，低置信字段保留模板默认值 |
| 中文比英文更宽 | 溢出和字号过小 | 中文容量重标、真实 glyph 度量、分页优先 |
| 任意换色破坏视觉 | 对比度和层级下降 | 角色映射、对比度门禁、明度受控修正 |
| Presenton 示例素材污染 | 出现无关图片或文案 | 离线 Sanitizer，照片全部排除，模板零示例正文 |
| 模板数量多但质量不稳 | 选择结果不可用 | 少量模板深度中文化，Golden Gate 后才发布 |
| HTML 与 PPTX 不一致 | 交付效果不可预测 | 共享 PositionedSpec 和字体资产，双输出截图对比 |
| 神州数码素材不权威 | 品牌和版权风险 | 只接收官方品牌包，未确认时不使用 Logo |

## 18. 是否需要多模态模型的复盘点

完成 R2 后再判断。如果以下问题仍频繁出现，才增加多模态风格分类器：

- OOXML 无法判断装饰语言；
- 模板前三名与人工选择长期不一致；
- 历史 PPT 使用大量背景图片而非矢量元素；
- 需要识别“科技、杂志、稳重、活泼”等隐性风格语义。

即使加入多模态模型，它也只输出受限的风格标签和模板排序特征，不输出 HTML、CSS、坐标和业务事实。

## 19. 下一开发动作

确认本方案后只执行 R1：先按 `docs/中文模板改造手册.md` 标定 Modern 的 Cover、Section、Key Message、Evidence、Process、Closing 六类页面容量，冻结字体、槽位、三档容量和边界语料，再用 `test1.pptx` 做换肤复测。六类页面全部形成 measured 容量前不扩展第二套模板，也不引入多模态模型。
