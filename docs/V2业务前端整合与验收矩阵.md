# 淘到宝引擎 V2 业务前端整合与验收矩阵

更新日期：2026-08-14
目标分支：`v2`

## 产品叙事

V2 正式业务端按销售磋商过程组织，不再把新增能力表现为彼此割裂的后台页面：

1. 磋商前：公开情报、画像补全建议、招标要求拆解和响应矩阵。
2. 磋商中：快速方案、方案演练和可信演示交付。
3. 磋商后：Deep Research、专家协作、复盘与可信资产沉淀。

资料库、经验库、原子能力库和长期客户画像是三阶段共用的数据底座。AI 运行与模型连接仍是只读观察面，不代替业务页面完成操作。

## 页面与真实接口

| 一级入口 | 主要能力 | 真实接口或边界 |
|---|---|---|
| 情报与招标 | 情报溯源、冲突治理、画像 Proposal 审批、招标拆解、响应矩阵审核与导出 | `/api/v1/intelligence/*`、`/api/v1/tenders/*`、`/api/v1/response-matrices/*` |
| 方案演练 | 两种上游入口、上下文固化、角色与难度、多轮回答、即时反馈、报告 | `/api/v1/rehearsals/*` |
| 快速方案 | 同客户多会话、简化检索与生成 | 保持 V0.5 冻结 quick 流程，不使用 Multi-Agent |
| Deep Research | 多阶段研究、证据快照、知识缺口、专家协作 | 复杂问题才进入 Multi-Agent |
| 演示交付 | 标准可信 HTML 与互动 HTML | 互动内容运行在无同源权限沙箱；AI 只编排 HTML/CSS，固定运行时和后端审计负责交互与安全 |
| 关于我们 | 产品故事、三位成员已确认项目分工与项目履历 | 不进入业务决策，不虚构个人教育、公司、奖项或经历 |

## 不可破坏边界

- 外部公开情报不能证明企业能力或企业历史事实。
- 画像 Proposal 必须人工确认；新会话信息不能自动覆盖长期画像。
- 经验和能力继续分库、分检索、分审核。
- 演练内容和评分不能自动修改画像、方案或可信资产，也不能作为绩效评价。
- 快速方案与方案演练不使用 Multi-Agent。
- 专家协作仍只能依附 Deep Research。
- 根目录冻结 `openapi.yaml` 和 `app/contracts/ai.py` 五个方法签名不得修改。
