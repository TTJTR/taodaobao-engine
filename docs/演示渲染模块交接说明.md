# V1.1 演示渲染模块交接说明

## 1. 交接结论

本分支已具备 V1.1 演示生成的可信基础链路、历史 PPT 脱敏风格解析、受限布局、HTML v2 shadow
Renderer、R1 中文 HTML/PPTX 可见样稿及自动化浏览器检查。当前成品定位是“可信且可验证的渲染
基线”，还不是可以对任意历史 PPT 直接产出商业级成品的最终 Renderer。

组长接手时，应以本提交为 V1.1 展示模块基线；不需要回退 FactLedger、FactBinding、EvidenceGuard
或事实哈希门禁。视觉效果需要在这些边界之后，通过受限模板、素材和布局选择提升。

## 2. 当前链路

```text
ReferenceDeck (.pptx)
  -> SafePPTXParser
  -> Theme / Master / sanitized_visual StyleProfile
  -> FactLedger (released Claim + granted Evidence)
  -> SlidePlan (AI 仅规划，不生成 HTML/CSS)
  -> Schema + FactBinding 预检
  -> Layout / RenderIR
  -> Final EvidenceGuard
  -> HTML Renderer v2 (shadow) / PptxGenJS R1 sample renderer
  -> 浏览器截图、溢出、对比度、事实哈希验收
```

正式后端演示控制面、Trust Gate、PresentationInputSnapshot 和 Provider 模式说明参见
`docs/V1.1后端可信编排与演示承接实现说明.md`。

## 4. R1 样稿与验证

生成命令：

```powershell
python -m scripts.generate_chinese_r1_showcase
python -m scripts.validate_chinese_r1_showcase
```

输出目录为 `.local/chinese-capacity-r1/`，被 Git 忽略，包含：

- `showcase.html`：浏览器直接打开的六页中文展示稿；
- `showcase.pptx`：同源 PPTX；
- `slide-01.png` 至 `slide-06.png`：桌面逐页截图；
- `showcase-desktop.png`、`showcase-laptop.png`、`showcase-mobile.png`：三视口截图；
- `validation-report.json` 与 `browser-validation.json`：自动化验收报告。

当前验证基线：1600x900、1440x900、390x844 三视口均无溢出；页面标题均存在；最低文字对比度
高于 4.5:1；样稿事实文本维持 SHA-256 一致。HTML 与 PPTX 只承诺事实一致、视觉近似，不承诺
像素级一致。

## 5. Presenton 的采用边界

本项目使用固定来源 `presenton/presenton@b940f7b4a51d473af830d96d441276af3540dae6` 的
`modern`、`executive`、`momentum` Template v2 作为受控设计输入，许可证为 Apache-2.0。

当前已经入库的是模板 JSON、无业务语义装饰、字体、许可证与完整 manifest。R1 样稿借鉴并实现了
其分栏封面、信息容器、大尺度几何、章节节奏与交错流程组合。不要将上游示例客户文本、图片、用户
系统或自由生成 HTML 的能力直接并入生产链路。

## 6. 当前效果为何仍有限

1. R1 只有六类代表页面，尚未把 Presenton Template v2 完整编译为可选择的受限 Element Tree。
2. 页面通过明确分支生成，尚未形成 20-30 个内容形状模板的自动选择能力。
3. 未接入经授权的企业图片、产品界面、数据图表和行业素材，视觉主体仍主要是抽象几何。
4. 历史 PPT 当前只提供 Theme/Master/脱敏几何；没有可靠的普通页面语义和视觉意图识别。
5. 浏览器验收当前检测边界、溢出、对比度和事实一致性，不等价于“好看”的视觉评分。
6. 没有 Office/LibreOffice 渲染截图，因此 R1 PPTX 只确认生成成功，未确认 Office 视觉回归。

## 7. 推荐接手顺序

### P0：将成熟模板变成运行时契约

把 Presenton Template v2 的白名单元素编译为 `TrustedTemplateSnapshot`：

- 固定背景、容器、文字槽、图片槽、装饰、图表槽；
- 每个槽位声明允许组件、容量、最小字号、占位尺寸与降级模板；
- 模板只能从注册表选取，Renderer 不接受任意 HTML、CSS 或 JavaScript；
- 保留模板来源、revision、资产哈希和许可证审计。

### P1：扩大内容形状覆盖

优先新增：双栏对比、三栏价值、指标、大数字、时间线、能力矩阵、系统架构、价值链、案例、行动计划。
每个事实组件必须保留 FactBinding；图表数值必须来自账本 numeric token。

### P2：引入视觉选择闭环

为同一 SlidePlan 生成 2-3 个受限模板候选，截图后按信息层级、对齐、留白、图文平衡、密度和品牌
一致性评分，再让人工确认 Golden Template。视觉评分器不拥有修改事实的权限。

### P3：受控视觉识别和素材

如需多模态模型，应只在 OCR/数值/敏感图像遮挡后的截图上输出视觉标签，如页面密度、图文比例、
列数、强调色与布局类别；不得将识别内容写入 FactLedger。图片和图标只从已审核资产库引用。

## 8. 不可破坏的约束

- AI 不能生成 HTML、CSS、坐标代码或 PPTX；只能输出 SlidePlan 与事实绑定建议。
- `verbatim` 文本、数字、单位、日期、来源和证据位置不能被 Layout 或 Renderer 改写。
- 所有业务组件必须通过两次 EvidenceGuard：布局前 FactBinding 预检与布局后最终检查。
- Renderer 不能访问业务数据库、调用 AI 或请求任意外部 URL。
- 历史 PPT 普通页文本、图表数值、备注、嵌入对象不能进入 StyleProfile 或运行时模板。
- 超出容量优先换模板、分页或拆页，不能静默截断或缩小到最小字号以下。

增加 PowerPoint 或 LibreOffice 的逐页截图回归；当前不可声称这项已完成。
